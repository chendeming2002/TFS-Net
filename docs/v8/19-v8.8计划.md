# v8.8 计划: QRB 的 Shift 共享与 Channel Mix Shift

> 创建于 2026-10-31
> 基线: v8.7-ssim (`configs/v8_5/v8_7_ssim_30ep.yaml`, 25.90 / 0.8433 / 0.3462)
> 实现: `models/golf_v7r/cross_rwkv_head_v8.py` 新增 `shift_share` 与 `cm_shift`
> 配置: `configs/v8_5/v8_8_a_30ep.yaml`、`configs/v8_5/v8_8_b_30ep.yaml`
> 测试: `tests/test_v8_8_shift_share.py` (6 项)

## 一、背景与问题

最优版本的 QRB 有四份独立 OmniShift (shift_r/g/k/v)。对照三个参考实现:

| | Spatial Mix Shift | Channel Mix Shift |
|---|---|---|
| Vision-RWKV | 1 次固定移位 + 3 个可学习混合系数 | 1 次 + 2 系数 |
| Restore-RWKV | 每流 1 个 OmniShift (K/V/R 共享) | 每流 1 个 (K/R 共享) |
| QRB 原型 (论文) | 4 个 Q-Shift | 2 个 (式 6) |
| **我们 (v8.7-ssim)** | **4 个独立 OmniShift** | **0** |

两个待分离的问题:

1. R/G、K/V 的 Shift 是否需要独立? (四份 → 按来源共享成两份)
2. Channel Mix 是否确实需要额外的局部空间上下文? (0 → 1, 恒等初始化)

## 二、实验矩阵

| 实验 | Spatial Mix Shift | Channel Mix Shift | 配置 | 验证目的 |
|---|:---:|:---:|---|---|
| Baseline | 4 | 0 | `v8_7_ssim_30ep` | 当前最优结构 (已有结果) |
| Exp-A | **2** (按来源共享) | 0 | `v8_8_a_30ep` | R/G、K/V 是否可以按来源共享 |
| Exp-B | **2** | **1** (恒等初始化) | `v8_8_b_30ep` | Channel Mix 独立 Shift 的贡献 |

两实验均为 30ep、batch 2、与基线同数据/优化器/seed/验证协议, 直接与
v8.7-ssim 的 25.90 / 0.8433 / 0.3462 对照。

执行顺序: **先 Exp-A, 再 Exp-B**, 排队在 v8.7-ssim2 (90ep) 训练结束后。
链式脚本内置门槛: 若 Exp-A 的 best PSNR 比 25.90 低超过 0.3 dB (即 < 25.60),
判定"明显性能下降", 自动跳过 Exp-B —— 此时应保留四份 Spatial Mix Shift,
Channel Mix 的问题改为单独验证 (见第五节)。

## 三、实现细节

### 3.1 Exp-A: 按来源共享 (`shift_share="by_source"`)

```python
if shift_share == "by_source":
    self.shift_r = self.shift_g = OmniShift(channels)   # R/G 共用一个实例
    self.shift_k = self.shift_v = OmniShift(channels)   # K/V 共用一个实例
```

同一个 Module 对象赋给两个属性: 梯度自然从两条路径汇入同一组参数;
`state_dict` 中出现两套同值键 (如 shift_r.* 与 shift_g.*), 加载兼容。
SPAB 与 v8.6 的 Q 输入残差均不变。参数量: 每头少 2 份 OmniShift
(C=32 时全模型 −3×2×1.8K ≈ −11K)。

### 3.2 Exp-B: Channel Mix Shift (`cm_shift=True`)

在 Channel Mix 输入前 (`post_norm` 之前) 加一份 OmniShift, **恒等初始化**:

```python
self.cm_shift = OmniShift(channels)
with torch.no_grad():
    self.cm_shift.alpha.fill_(0.0)
    self.cm_shift.alpha[0].fill_(1.0)     # 初始输出 = x
```

为什么这样初始化: 默认 OmniShift 的 alpha 是 1/√4, 初始输出**不是**恒等
(只有一半走直通), 会立刻改变 Channel Mix 的输入分布 —— 那样 Exp-B 的性能
变化就无法区分"来自 Shift 的学习"还是"来自初始分布被扰动"。恒等初始化
使初始行为与 Exp-A 逐元素一致 (单测实测差 0.0e+00), 性能变化只能来自训练中
Shift 学到的东西。

梯度解锁的级联 (实测, 均为设计好的起点, 非死锁):

| 步 | cm_out | alpha | conv 分支 |
|:--:|:--:|:--:|:--:|
| 1 | ✓ | ✗ (被 cm_out 零初始化挡住) | ✗ |
| 2 | ✓ | ✓ | ✗ (alpha=0 挡住) |
| 3+ | ✓ | ✓ | ✓ |

与既有 channel_mix 末层零初始化的"两步起步"同族, 只是多一级。

### 3.3 不变的部分

- 基线 v8.7-ssim 的代码路径: 两个新参数默认 `none`/`False`, 行为逐位不变;
- Encoder 头 (`SpatialRWKVHeadV8`) 与 `receptance` 模式: 新参数不进入其
  head_kwargs (TCA 中仅 cross 系列头接收);
- SPAB、Q 输入残差、SGRFv10、损失配置全部不变。

## 四、判据

与基线 25.90 / 0.8433 / 0.3462 对照:

| 检查项 | 通过标准 |
|---|---|
| PSNR | ≥ 25.80 (下降 ≤ 0.10 视为持平; < 25.60 判明显下降) |
| SSIM / LPIPS | 不低于基线 −0.003 / +0.005 |
| 分支相对误差 | 不崩溃 (N、M < 1.0) |
| 参数量 | Exp-A ≈ 1.312M, Exp-B ≈ 1.317M (待 GPU 实测确认) |

结论解读:
- Exp-A 持平 → 四份 Shift 冗余, 可按来源共享 (省 11K 参数, 推理更快);
- Exp-A 下降 → R/G (或 K/V) 确实需要独立 Shift, 保四份;
- Exp-B 相对 Exp-A 提升 → Channel Mix 需要局部上下文;
- Exp-B 相对 Exp-A 持平 → Channel Mix 的逐位置职责不需要移位, 维持素形式。

## 五、若 Exp-A 明显下降的后续路径

按既定原则不急加 Channel Mix Shift, 改为单独验证第三种拆分:
`shift_share="rg_only"` (R/G 各一份独立、K/V 共享一份) 或反向, 用于定位
"独立性的需求在 Q 侧还是 KV 侧"。该变体未实现, 等 Exp-A 结果出来再决定。

## 七、v8.8-B 的 Encoder Channel Mix Shift (2026-10-31 追加)

按用户指令, Encoder RWKV Block (含聚合器 frame_encoder) 的 Channel Mix
也加上 Token Shift, 与 QRB 的 cm_shift 同一实现、同一恒等初始化:

- `SpatialRWKVHeadV8` 新增 `cm_shift` 参数 (恒等初始化 OmniShift);
- `RWKVEncoderBlock` / `FrameEncoder` / `GolfNet_v8` 逐层透传,
  模型级开关为 `enc_cm_shift`;
- **聚合器不启用** (用户裁决 2026-10-31): `TemporalAggregator_G` 保持原样,
  其内部 frame_encoder 不接收 cm_shift —— 聚合器的 frame_encoder 用途是
  逐帧独立编码后做均值聚合, 与编码器三尺度的连续特征提取不同, 不跟随;
- B 配置启用: `q_shift_share: by_source` + `cm_shift: true` (QRB)
  + `enc_cm_shift: true` (仅编码器三个尺度)。

冒烟实测: 编码器 cm_shift alpha 为 [1,0,0,0], 聚合器 frame_encoder 的
cm_shift 为 None; 参数量 1.3271M; 前向/反向正常。

注: 首次启动曾误将聚合器一并启用 (参数量 1.3316M), 按用户指令回退并
从第 1 轮重启, 旧日志已清空。

注意: B 实验因此同时含三个变量 (Shift 共享、QRB cm_shift、Encoder cm_shift),
与计划的单一变量原则不同; 若结果与基线有差异, 归因需要拆分。

## 九、OmniShift 分支置零消融 (推理期干预, 2026-11-01)

工具: `scripts/diag_shift_ablation.py`。对 v8.8-B best (ep25), 把每个 OmniShift 的
1×1 / 3×3 / 5×5 分支 alpha 单独置零, 3 段序列 128 中心裁剪 (口径同下为快探针;
基线 26.97 dB)。置零只衡量训练后的即时依赖, 不等价于重训练删除该分支。

### 9.1 完整结果 (ΔPSNR 相对基线, 正为变好)

|---|---:|---:|---:|
| enc.scale1.spatial | +0.01 | −0.39 | **−2.87** |
| enc.scale1.cm | +0.01 | −0.00 | −0.01 |
| enc.scale2.spatial | −0.01 | −0.06 | −0.29 |
| enc.scale2.cm | +0.00 | +0.00 | **−1.48** |
| enc.scale3.spatial | +0.00 | +0.00 | −0.73 |
| enc.scale3.cm | −0.00 | −0.00 | **−0.90** |
| tca.attn_N.rg | +0.03 | −0.01 | −0.34 |
| tca.attn_N.kv | +0.03 | +0.07 | −0.00 |
| tca.attn_N.cm | −0.00 | +0.00 | +0.04 |
| tca.attn_L.rg | −0.01 | +0.00 | **−2.83** |
| tca.attn_L.kv | +0.00 | +0.00 | +0.19 |
| tca.attn_L.cm | −0.04 | −0.00 | **−0.75** |
| tca.attn_M.rg | −0.00 | −0.00 | +0.08 |
| tca.attn_M.kv | +0.00 | +0.00 | +0.01 |
| tca.attn_M.cm | +0.00 | −0.00 | +0.00 |

### 9.2 判读

1. **5×5 是唯一有实质贡献的卷积分支, 且集中在六处**: enc.scale1.spatial (−2.87)、
   tca.attn_L.rg (−2.83)、enc.scale2.cm (−1.48)、enc.scale3.cm (−0.90)、
   tca.attn_L.cm (−0.75)、enc.scale3.spatial (−0.73)。其余所有 5×5 置零的
   影响都在 ±0.35 dB 内。
2. **1×1 分支在所有 15 处都可以无代价移除** (ΔPSNR ∈ [−0.01, +0.03], 全部
   不超过噪声)。alpha 分布里 1×1 占 19–31%, 但置零无影响 —— 它是参数偏好,
   不是功能贡献。
3. **3×3 分支同样全部可移除** (最大 −0.39)。这与 alpha 分布一致 (多数位置
   3×3 被压到 0–13%), 但注意 enc.scale1.spatial 的 3×3 alpha 占 18%, 置零
   也只掉 0.39。
4. **attn_M 的所有 Shift 分支都可无代价移除** (含 5×5 的 +0.08)。上一节
   alpha 报告里 attn_M.rg 的 5×5 占 50.1% —— 占比最高的分支置零反而
   没有影响, 是"参数偏好 ≠ 功能贡献"最直接的证据。
5. **分支输出 (bstd N/L/M) 在全部干预下几乎不动** (变化 <0.006),
   即置零的影响全部经由重建路径体现, 不改变三路输出的量级。

### 9.3 结论

alpha 分布与功能贡献**部分对应但不等同**: 5×5 的贡献真实存在 (六处),
但 alpha 占比高不等于贡献大 (attn_M.rg.5×5 反例), 占比低也可能有贡献
(enc.scale2.cm.5×5 占 33% 贡献 −1.48 dB, 而 1×1 同占 0.2% 无贡献,
真正的判据是置零代价)。

若做推理精简: 可移除全部 1×1 与 3×3 分支 (30 个卷积 × 每处 C 个核),
保留 5×5; 但这是推理期结论, 重训练时删分支允许其余分支补偿, 结论不外推。

### 10.4 判读

v8.8-B 在 DID 上**低于 v7r_v3 约 1.1–1.3 dB** (同 frac 口径), SSIM 低约
0.02, LPIPS 差约 0.03。跨数据集泛化不如旧版 v7r_v3, 但优于 r2。

可能的原因 (未验证, 仅列出):
1. v8.8-B 的全部结构演进都在 SDSD 的分布内完成 (频带目标、SGRF、SSIM 损失
   都以 SDSD 统计为前提), 对 DID 的退化分布过拟合;
2. v7r_v3 的三分支是并行动态融合, 逐像素权重可以按输入分布切换主导路;
   v8.8-B 的 SGRF 是固定 N→L→M 串接, 顺序在 DID 上可能不匹配
   (DID 的退化以全局压暗为主, 串接的先去噪后提亮顺序未必合适);
3. MS-SSIM 损失项在 SDSD 上调优 (w=0.1), 对 DID 的对比度分布敏感。

这是跨数据集的已知风险, 不是 v8.8-B 在 SDSD 上最优地位的否定。若论文需要
DID 数字, 建议同时报告 v7r_v3 与 v8.8-B 并说明各自训练与结构差异。
