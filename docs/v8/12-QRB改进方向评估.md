# TaskQueryAttention 的改进方向: 外部建议的评估与落点

> 创建于 2026-10-24
> 评估对象: 外部对 `TaskQueryAttention` 内 `QueryRWKVBlock` 的改进建议
> 涉及代码: `models/golf_v7r/cross_rwkv_head_v8.py`
> 本文档只做评估与记录, 不改变代码。

## 一、外部建议的准确概括

建议的主题是: 当前 QRB 里 Q 只通过门控间接影响输出, 是否没有充分利用 Q 的任务特异性
信息。由此提出三个候选方向:

- **A. Q 条件化 KV 调制**: 在进入 WKV 扫描前, 用 Q 生成通道级缩放与偏移, 调制 V。
- **B. 显式 Q 内容支路**: 在现有输出之外加一条 Q 的直连支路, `O = SiLU(G)⊙A + λψ(Q)`,
  λ 零初始化。
- **C. 改进 R/G 生成**: 让门控显式利用不同尺度的 Q 特征, 例如 `G = σ(ψ_g([Q, DWConv(Q)]))`。

在第二份补充里, 建议进一步明确: 保留双门 R/G、乘法作为主要调制方式, 优先在双门之上
加一条受控的加性 Q 支路, 而不是合并为单门。

## 二、与现有实现的核对

外部建议对我们的结构描述有一处偏差, 必须先纠正, 否则三个方向的判断都建立在错误前提上:

外部写的是 `A = LN_head(R ⊙ Z)`。我们实际实现的是:

```
A_i = g_i ⊙ head_norm(r_i · wkv_i)        (i = 1..4 逐头)
out = cat(A_1..A_4) · W_a
```

与外部描述的差别有两处:

1. **R 的乘法发生在归一化之前**, 不是之后。`head_norm` 对 `r · wkv` 的整体幅度做了归一,
   这与外部"R 的乘法调制可能削弱 Q 的幅值信息"的问题描述**相反**: 在我们的实现里,
   R 改变的是各通道的相对比例, 整体幅度由归一化承担。外部担心的"幅值被乘法削弱"恰恰
   是这条归一化在保护。
2. **G 的 SiLU 门控在归一化之后**, 是输出侧的调节, 不是在 WKV 之前的 KV 调制。

这两处都不影响三个方向本身的可行性, 但影响对方案 A 的判断: 方案 A 要让 Q 调制 KV,
而我们现有的 K/V 输入已经是从特征投影出来的, 在进入扫描之前还有一次 Q-Shift。
方案 A 所说的"Q 改变被读取的内容"在我们的实现里已经部分存在 (Q-Shift 的四个投影
各由独立输入产生), 只是调制发生在投影层面而不是扫描层面。

## 三、三个方向的可行性评估

按"与现有证据的兼容性"排序, 与外部建议的优先级不同。

### 方案 C (改进 R/G 生成): 优先

理由很直接: 四次实验里, N 与 M 的相对误差稳定在 0.66 到 0.73, 换过查询机制
(receptance 到 cross_rwkv)、换过 K/V 来源 (滤波到全带)、换过融合方式
(additive 到串接门控), 这个数值都没有明显下降。这意味着 Q 的任务特异性信号在
当前结构里没有被有效传递到输出。

方案 C 的改动最小: 只在 R 与 G 的投影之前加一次局部上下文, 或让 G 同时带通道级与
空间级调制。它直接针对"门控表达能力"这个假设, 可以单独消融。

风险: 如果瓶颈不在门控, 收益有限。

### 方案 A (Q 条件化 KV 调制): 第二

外部的理由是让 Q 参与 KV 的构造。这一点在我们这里已经部分兑现 (Q-Shift 的独立
投影), 但**方向不同**: 外部想让 Q 调制 V 的幅值, 我们现有的是用 Q 生成 K 与 V 的
输入, 两者都进扫描。

有一个实测证据反对把 V 的调制放在扫描之前: 我们的 WKV 核是自定义 CUDA 算子, 输入
的 V 必须满足 `[num_dirs, L, C]` 的布局, 且已经在 `bi_wkv_list` 的 `clamp(-8, 8)` 里
做了数值约束。若在扫描前对 V 做逐通道缩放与偏移, 幅度可能被推到 clamp 的边界, 反而
引入新的数值问题。

如果做, 建议从轻量版本开始: 只对 K 做调制 (K 决定检索的权重分布, 不影响数值稳定性),
V 保持不变。这样风险最小, 且能单独回答"Q 是否改变了哪些内容被读取"。

### 方案 B (显式 Q 内容支路): 最后

外部的建议是加一条 `λψ(Q)` 的直连支路。这条支路与我们的 `residual_freeze` 设计直接
冲突: 我们在 additive 融合里已经验证过, 当模型有一条不经过任何门控的直通路径时,
训练会让最终输出大量依赖这条路径, 掩盖三分支的问题 (v7.5 的 `residual_gamma` 实测
增长到 0.47 到 0.60, 因此被冻结为 0)。Q 内容支路在结构上就是同一种直通, 只是
换了个来源。

如果要验证, 应当把它与现有 frozen residual 对照, 而不是在 frozen residual 的基础上
再叠加。且 λ 必须严格监控: 若 λ 在训练中涨到主导量级, 说明模型在绕开门控, 这与
v7.5 的塌缩是同一类问题。

## 四、不建议做的事

按外部建议原文里已经写明的边界, 结合我们的实测记录, 有三件事明确不做:

1. **不改三个分支的结构。** 外部说"三个分支的模块结构相同", 这在 v8.5 之后已经不成立:
   N、L、M 的输入来源与目标频带不同, 各自的归纳偏置也不同 (N 的通道注意力、
   L 的 Retinex、M 的运动精化)。给它们设计三套结构是过去的方向, 与当前现状不符。
2. **不一次叠加三个方案。** 外部自己也说"保留基线, 依次测试"。上一轮 SGRFv9 的失败
   部分原因就是同时改了限幅、幅度、门控多个变量, 无法归因。
3. **不动 KV 的频带分工。** 全带 KV 已经验证有效 (24.36 dB 与噪声专属性),
   方案 A 若实施只作用在投影层, 不改变 KV 的来源。

## 五、若要做, 建议的最小实验

只做一个变量, 且只做最轻量的形式:

| 实验 | 改动 | 回答的问题 |
|---|---|---|
| C1 | R/G 投影前加一次局部上下文 (3×3 深度卷积) | 门控表达能力是否是瓶颈 |
| C2 | 在 C1 基础上, G 同时输出空间级与通道级两路 | 门控是否需要两种尺度的调制 |

C1 用现有 head 的单测就能验证梯度与输出形状; 与当前 `cross_rwkv` 直接对比,
其他一切 (KV 来源、融合、监督) 不动。判据沿用已有的一套: N、M 的相对误差、
置零代价、加噪响应, 与 fullkv / a_lite / SGRFv8 / SGRFv10 四组基线逐项对照。

## 六、结论

外部建议的三个方向都值得考虑, 但它们的优先级与我们项目当前的状态不完全一致。
按已有证据 (四轮实验里 N、M 的相对误差稳定在 0.7 附近, 换查询与换 KV 都没有突破),
瓶颈更可能在门控的表达能力, 而不是 KV 的内容编码或 Q 的直通支路。

因此我的建议是: 先做方案 C 的轻量形式 (C1), 验证门控表达是否真是瓶颈;
若 C1 无效, 再考虑方案 A 的 K-only 调制; 方案 B 不建议做, 它与我们已经验证过的
frozen residual 设计冲突。

按第二轮审查后的修正, C 的初始化已从默认初始化改为零初始化 (见第八节)。
A、B 在审查中通过, 设计定义不变。三个变体完成独立训练后, 再依据实际指标决定
是否与 G + SGRFv10 组合, 不预先假定某一方案有效。

## 七、三个变体已实施 (2026-10-24)

### 7.1 实施位置

三个变体都只继承 `CrossRWKVHeadV8`, 不重写扫描逻辑, 各自的改动集中在一处:

| 变体 | 类 | 文件 | q_mode | 改动 |
|---|---|---|---|---|
| A (K 调制) | `CrossRWKVHeadKvMod` | `models/golf_v7r/qrb_variants.py` | `kvmod` | Q 池化+线性得通道缩放/偏移, 扫描前调制 K |
| B (Q 内容支路) | `CrossRWKVHeadQPath` | 同上 | `qpath` | 输出加 λ·ψ(Q), λ 零初始化 |
| C (门控局部上下文) | `CrossRWKVHeadGateCtx` | 同上 | `gatectx` | R/G 的 Q-Shift 后各加一次 3×3 深度卷积 (残差注入) |

### 7.2 与原结构的关系

三个变体都满足: 初始状态与原 `cross_rwkv` 逐元素一致, 或仅在新增参数非零后才有差异。

| 变体 | 初始一致性 | 触发条件 |
|---|---|---|
| kvmod | 逐元素一致 (α=β=0) | α 或 β 非零 |
| qpath | 逐元素一致 (λ=0) | λ 非零 |
| gatectx | 与原结构输出不同 | 始终 (局部上下文是非平凡改动) |

### 7.3 检查与回归

`tests/test_qrb_variants.py` 7 项全过: 三者前向/反向正常、kvmod 与 qpath 的初始一致性、
调制与支路在非零后生效、gatectx 与原结构输出不同、三者新增参数均有梯度。

回归: `test_cross_rwkv_head_v8` (11 项)、`test_sgrf_v10` (5 项) 全部通过。

### 7.4 参数量

| 变体 | 全模型参数量 | 新增参数 |
|---|---:|---:|
| cross_rwkv (基线) | 1.2354M | — |
| kvmod | 1.2419M | +6.5K |
| qpath | 1.2385M | +3.1K |
| gatectx | 1.2371M | +1.7K |

三者都只比基线多 1.7K 到 6.5K, 与全模型的 1.235M 相比可忽略。

### 7.5 尚未启动训练

三个变体只完成了实现与检查, 未训练。是否启动 30 轮训练、以及与哪个融合方式组合
(并行 additive / 串接 SGRFv8 / SGRFv10), 由用户决定。

按第五节的原则, 若启动, 建议只选一个变体, 用相同的 30 轮预算与相同的上游配置,
与 G + SGRFv10 的基线直接对比。

## 八、第二轮代码审查结果 (2026-10-24)

按三类汇报。新增测试 `tests/test_qrb_variants_review.py` (7 项全过), 第一轮测试
`tests/test_qrb_variants.py` (7 项) 与全部 10 个既有测试套件均无回归。

### 8.1 已确认

**方案 A (K-only 调制, `CrossRWKVHeadKvMod`)**

- `q_scale_a` / `q_scale_b` 是 `nn.Parameter`、可训练、严格零初始化 (`torch.zeros(C)`),
  初始化时 K 与基线逐元素一致, V 完全不变;
- 两者首步即有梯度;
- 调制后 K 的数值范围: 实测 (C=32, H=W=128) |K| 从 4.32 变到 4.50, scale 范围
  [0.91, 1.09], shift 最大 0.05, 远低于 clamp(-8, 8) 的阈值, CUDA 扫描稳定;
- 监控已补齐: `_last_k_mod` 记录 `scale_mean` / `scale_absmax` / `shift_absmax` /
  `k_absmax_post` (只记录, 不改计算)。

**方案 B (Q 内容支路, `CrossRWKVHeadQPath`)**

- `q_lambda` 是 `nn.Parameter`、严格零初始化, 初始输出与基线逐元素一致;
- 首次 backward 时梯度 1.2378, 优化器一步后 ψ(Q) 的权重仍有梯度;
- 监控已补齐: `_last_q_path` 记录 `lambda` / `side_rms` / `main_rms` /
  `side_to_main` (只记录, 不改计算)。

**方案 C (R/G 局部上下文, `CrossRWKVHeadGateCtx`)**

- `ctx_r` 与 `ctx_g` 是独立的 3×3 深度卷积, 只作用于 R/G 投影; K/V 与 WKV 扫描
  完全不变 (与基类逐元素一致);
- 梯度、形状、数值稳定性正常。

**实验隔离**

- 三个 `q_mode` 互不叠加: 逐一核对 `hasattr` 确认 kvmod 没有 q_lambda/ctx_r,
  qpath 没有 q_scale_a/ctx_r, gatectx 没有 q_scale_a/q_lambda;
- 基类的归一化、R/G/K/V 投影顺序、WKV 调用、残差与 channel mix 均未被修改,
  所有继承关系成立。

### 8.2 存在问题

- **gatectx 的初始残差 RMS 比偏高 (0.596)**: `ctx(x)` 的 RMS 是输入的 0.60,
  门控的初始条件因此偏离了纯 Q-Shift。已按最小改动修正: 把 `ctx_r` / `ctx_g`
  的权重零初始化, 使 C 从与原版一致的状态开始学习; 修正后初始逐元素一致
  (误差 0.0), 多步优化后卷积离开零 (5 步权重幅度 0.005, 梯度 473.18)。

### 8.3 尚未验证

- 三个变体的训练行为未验证, 监控数据只在初始化与单步测试中确认存在, 未在
  真实训练中观察其演化;
- 与原 cross_rwkv 在真实数据上的 PSNR / SSIM / LPIPS 差异未测;
- 与融合方式 (additive / SGRF) 的组合行为未测。

审查结论: 实现与设计目标一致, 没有阻断问题。gatectx 的初始残差幅度是唯一需要
关注的数字, 留作训练前排查项。是否启动训练由用户决定, 本轮不启动。
