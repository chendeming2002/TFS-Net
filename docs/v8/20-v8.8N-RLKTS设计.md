# v8.8N: RLK-TS (残差大核 TokenShift) 的统一 QRB 重构

> 创建于 2026-11-01
> 基线: v8.8-B (`configs/v8_5/v8_8_b_30ep.yaml`, 26.05 / 0.8432 / 0.3426)
> 性质: 设计 + 实验方案, 按用户裁决执行
> 代码: `models/golf_v7r/rlk_ts.py` (待实现)

## 一、动机: 置零消融暴露的 OmniShift 结构问题

v8.8-B 的 45 组置零消融 (本文件第九节) 给出三个事实:

1. **1×1 分支在全部 15 处都可无代价移除** (ΔPSNR ∈ [−0.01, +0.03]);
2. **3×3 分支贡献有限** (最大 −0.39 dB);
3. **5×5 是唯一有实质贡献的卷积分支**, 集中在六处
   (enc.scale1.spatial −2.87, tca.attn_L.rg −2.83, enc.scale2.cm −1.48,
   enc.scale3.cm −0.90, tca.attn_L.cm −0.75, enc.scale3.spatial −0.73)。

结论: OmniShift 把空间混合能力分散在多个独立卷积分支中, 但功能贡献集中在
5×5 一支; 其余分支是参数偏好而非功能 (attn_M.rg.5×5 alpha 占 50.1% 置零反而
+0.08, 是最直接的证据)。设计新算子的依据必须是置零代价, 不是 alpha 分布。

## 二、RLK-TS 定义

```
RLKTS(x) = x + γ · (DW_5x5(x) − x)
```

- `DW_5x5`: 5×5 Depthwise Conv;
- 卷积核初始化: 中心位置 1、其余 0 (初始时 DW(x) = x);
- γ 初始化 0.1, 可学习标量。

初始时 `RLKTS(x) = x` (双保险: 核是恒等 + γ 很小), 训练从恒等出发, 由 5×5
核逐渐学习邻域增量, 不从第一步改变输入统计分布。

与 OmniShift 的对照:

| 项 | OmniShift | RLK-TS |
|---|---|---|
| 结构 | 恒等 + 1×1 + 3×3 + 5×5 并联, alpha 加权 | 恒等 + 单个 5×5, γ 插值 |
| 初始行为 | 非恒等 (alpha=1/√4, 输出是四路平均) | **恒等** |
| 参数 (C=32) | ~1.1K (三核) + 4 alpha | ~0.8K (单核) + γ |
| 推理融合 | 可合并为 5×5 | 可合并为 5×5 (`(1−γ)·δ + γ·W`) |

设计来源: 用户方案 (Residual Large-Kernel TokenShift), 依据是消融里 5×5 的
主导贡献。注: 该证据证明 5×5 分支的重要性, 不证明它学到的是低频信息;
RLK-TS 是待验证的简化设计, 不是已验证的最优形式。

## 三、统一 QRB 拓扑 (三路 N/L/M 相同结构)

| 位置 | 输入 | TokenShift | 共享关系 |
|---|---|---|---|
| SM-Q | center_feat | RLK-TS | R/G 共享一份 |
| SM-KV | context_feat | RLK-TS | K/V 共享一份 |
| CM | SM 输出 a | RLK-TS | R'/K' 共享一份 (Shift 在 LN 与投影之前) |

要点:

1. **SM 与 CM 用同族算子、不同实例**: RLK-TS 类相同, 参数各自独立,
   功能差异由输入来源与放置位置体现, 不机械共用同一空间混合策略
   (SM 为 WKV 扫描准备上下文, CM 建立局部空间与通道变换的联系)。
2. **共享关系严格保留**: R/G 共享、K/V 共享 (v8.8-B 的 by_source 组织),
   CM 的 R'/K' 共享 —— R' 与 K' 从同一份 LN(RLKTS(a)) 产生, V' 仍由
   K' 的非线性变换生成, 不单独设 Shift。
3. **三路完全同构**: 相同模块定义、相同参数量、相同数据流拓扑,
   只保留各自独立的可学习参数。不为 N/L/M 分别设计不同 Shift
   (M 路 5×5 当前无贡献不等于 M 不需要空间上下文, 不为理论直觉加机制)。
4. **Encoder 是否同样替换**: v8.8-B 里 Encoder 也用 OmniShift
   (spatial 与 cm 两处)。消融显示 enc.scale1.spatial.5×5 (−2.87) 与
   enc.scale2/3.cm.5×5 (−1.48/−0.90) 贡献显著, 因此 Encoder 同步替换为
   RLK-TS (spatial 一处 + cm 一处), 与 QRB 用同一类。
   聚合器 frame_encoder 按既定裁决继续不动。

## 四、不叠加与不做的事

| 项 | 理由 |
|---|---|
| 不与 `CrossRWKVHeadGateCtx` (R/G 后 3×3 残差上下文) 叠加 | 两者是不同性质的改动 (加 ctx vs 换 Shift 算子), 第一轮不混 |
| 不做 Directional TokenShift (方向位移 β_d) | 无实验证据支持其优于 5×5 DWConv, 仅列为后续候选 |
| 不给 N/L/M 设计不同的 Shift 算子 | 破坏三路统一拓扑; M 的问题不在局部混合能力 |
| 不引入更复杂的多尺度组合 | 消融明确显示 1×1/3×3 无功能贡献 |

## 五、实现要点

`models/golf_v7r/rlk_ts.py`:

```python
class RLKTS(nn.Module):
    """残差大核 TokenShift: x + γ·(DW5x5(x) − x), 初始恒等。"""
    def __init__(self, channels: int):
        super().__init__()
        self.dw = nn.Conv2d(channels, channels, 5, 1, 2,
                            groups=channels, bias=False)
        self.gamma = nn.Parameter(torch.tensor(0.1))
        with torch.no_grad():                     # 中心 1 其余 0 → DW(x)=x
            self.dw.weight.zero_()
            for c in range(channels):
                self.dw.weight[c, 0, 2, 2] = 1.0

    def forward(self, x):
        return x + self.gamma * (self.dw(x) - x)

    @torch.no_grad()
```

接入方式与 v8.8 相同的开关风格: `shift_kind="omni"|"rlk"` 控制
(SM 的 R/G、K/V 两处, CM 一处, Encoder 的 spatial/cm 两处),
`enc_cm_shift` 继续控制 Encoder CM 是否启用。默认 `omni`, 行为不变。

## 六、实验方案 (用户裁定的验证顺序)

三组单变量, 均以 v8.8-B 为基线, 30ep、同数据/优化器/seed/验证协议,
三路 N/L/M 结构一致:

| 实验 | 改动 | 配置 | 回答的问题 |
|---|---|---|---|
| N1 (SM-only) | 仅 SM 的 Q/KV Shift 换 RLK-TS, CM 保持 OmniShift | `v8_8n1_30ep` | 5×5 简化是否保留 SM 所需空间上下文 |
| N2 (CM-only) | 仅 CM 的 Shift 换 RLK-TS, SM 保持 OmniShift | `v8_8n2_30ep` | CM 是否确实需要独立的局部空间混合 |
| N3 (SM+CM) | 两处都换 (N1、N2 至少一项有正向结果后) | `v8_8n3_30ep` | 组合是否进一步受益 |

注意: N1/N2 相对基线各含两个子改动 (QRB 与 Encoder 的对应侧同步替换),
因为 Encoder 与 QRB 用同一 Shift 体系; 若需更细归因可再拆, 但第一轮按
SM/CM 两条线分离即可。

### 判据 (相对 v8.8-B 的 26.05 / 0.8432 / 0.3426)

| 检查项 | 通过标准 |
|---|---|
| PSNR | ≥ 25.95 (下降 ≤ 0.10 视为持平) |
| SSIM / LPIPS | 不低于基线 −0.003 / +0.005 |
| 分支相对误差 | 不崩溃 (N、M < 1.0) |
| 参数量 | ~1.32M 附近 (Shift 净减约 10K) |

结论解读:
- N1 持平或更好 → SM 的多分支 OmniShift 可简化为 RLK-TS (省参数, 结构更清晰);
- N1 明显下降 → 5×5 置零的即时依赖不等于可替换, 并联分支存在置零测不出的
  冗余补偿;
- N2 持平 → CM 的移位本来就弱 (v8.8 恒等初始化起步), RLK-TS 不损失;
- N3 取 N1/N2 中较优方向组合。

### 8.3 有趣的对照: 扰动诊断里的反事实数字反而更好

诊断口径 (10 序列 256 裁剪, 与训练验证不同):

| 项 | v8.8N | v8.8-B |
|---|---:|---:|
| 干净 PSNR | 26.34 | 26.15 |
| N 置零代价 | **−4.648** | −4.420 |
| 加噪 σ=0.05 | 15.90 | 14.70 |
| 模糊 9px | **25.76** | 25.12 |

诊断口径下 v8.8N 反而更好。两个口径的差别在数据范围 (10 序列 vs 10 段视频全帧)
与裁剪 (256 中心 vs 整图)。训练验证 (1244 帧全图) 是既定主判据, 结论以它为准:
v8.8N 不通过。诊断数字说明 RLK-TS 学到的表示在局部裁剪上不弱, 但整图全帧
泛化略差 —— 大核恒等起步可能需要更长训练才能在全图分布上追平。

### 8.4 结论

1. **RLK-TS 不采用**: 主判据三项全部低于 v8.8-B。置零消融的"5×5 是唯一有效
   分支"是推理期事实, 不能外推为"只留 5×5 重训练等价" —— 并联的 1×1/3×3
   在重训练中承担了置零测不出的补偿作用。这正是设计文档开头注明的那条边界。
2. v8.8-B 保持当前最佳 (26.05 / 0.8432 / 0.3426)。
3. 保留价值: RLKTS 模块与 shift_kind 开关留在代码里 (默认 omni 不影响任何
   现有路径); 教训写入文档 —— 后续 Shift 类改动应以重训练对照为准, 置零
   消融只用于定位依赖, 不用于预测替换收益。
