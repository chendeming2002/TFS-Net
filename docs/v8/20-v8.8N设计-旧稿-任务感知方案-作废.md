# v8.8N: 任务感知的 TokenShift 重新设计

> 创建于 2026-11-01
> 依据: v8.8-B 的 45 组置零消融 (`19-v8.8计划.md` 第九节) + alpha 分布报告
> 性质: 设计与实验方案, 待决策。按用户指示命名为 v8.8N。
> 前置结论: 所有置零数据均为推理期干预, 未经过重训练验证, 不能直接认为新结构
> 优于 v8.8-B。

## 一、证据基础 (来自 v8.8-B 的实测)

置零消融的六个高贡献分支 (ΔPSNR < −0.5 dB):

| 位置 | ΔPSNR |
|---|---:|
| enc.scale1.spatial 5×5 | −2.87 |
| tca.attn_L.rg 5×5 | −2.83 |
| enc.scale2.cm 5×5 | −1.48 |
| enc.scale3.cm 5×5 | −0.90 |
| tca.attn_L.cm 5×5 | −0.75 |
| enc.scale3.spatial 5×5 | −0.73 |

三条关键事实:

1. **只有 5×5 有实质贡献**, 且集中在 Encoder 浅层与 TCA 的 L 路;
2. **1×1 与 3×3 在全部 15 处可无代价移除** (ΔPSNR ∈ [−0.39, +0.07]);
3. **M 路的九个 Shift 干预全部在 ±0.08 dB 内** —— alpha 占比最高的
   attn_M.rg.5×5 (50.1%) 置零反而 +0.08, 参数偏好不等于功能贡献。

## 二、设计原则: Task-aware Spatial Context Injection

不再假设所有 RWKV 投影需要相同形式的局部空间变换。三种 TokenShift 的职责
不同, 形式也应不同:

| 部件 | 输入 | 职责 | 需要的空间信息 | 结论 |
|---|---|---|---|---|
| Q-SM (R/G) | center_feat | 决定读取方式 | 查询位置的局部结构 | 仅 L 需要 5×5; N/M 用 Identity |
| KV-SM (K/V) | context_feat | 构造检索的 K/V | 已由 Encoder 提供 | Identity (首选) |
| CM | Spatial Mix 输出 | 通道融合 | 位置保持, 仅补必要邻域 | 仅 L 需要 5×5; N/M 用 Identity |

Encoder 侧的结论保留: scale1.spatial 与 scale2/scale3.cm 的 5×5 有真实贡献,
Encoder 的 Shift 不在本方案精简范围内 (高贡献分支里 Encoder 占四席)。

## 三、新模块 (只实现两个)

```python
class LargeKernelResidualShift(nn.Module):
    """X' = X + γ · DWConv_5x5(X); γ 零初始化 → 初始为 Identity。"""
    def __init__(self, channels):
        self.conv = nn.Conv2d(channels, channels, 5, 1, 2, groups=channels, bias=False)
        self.gamma = nn.Parameter(torch.zeros(1))
        # conv 用 kaiming 初始化 (γ=0 保证初始恒等, 梯度两步可达:
        # 第一步 γ 有梯度, 第二步 conv 开始学习 —— 与既有零初始化模式同族)

class IdentityShift(nn.Module):
    """不进行任何空间变换。"""
```

不开发动态路由, 不增加分支, 不实现 C2 (Vision-RWKV 式混合)。

## 四、v8.8N 的最终结构 (若第三阶段通过)

| 位置 | Shift |
|---|---|
| N.Q-SM | Identity |
| L.Q-SM | LargeKernelResidualShift |
| M.Q-SM | Identity |
| N.KV-SM | Identity |
| L.KV-SM | Identity |
| M.KV-SM | Identity |
| N.CM | Identity |
| L.CM | LargeKernelResidualShift |
| M.CM | Identity |

两条实现约束:

1. L.Q-SM 与 L.CM 的 5×5 **不共享参数** —— 前者处理查询特征, 后者处理
   全局交互后的通道融合, 输入分布与功能不同;
2. SPAB 仍只作用于 R (v8.6 起的行为), LargeKernelResidualShift 在 SPAB
   之前、作用于共享的 Q 特征 (R/G 共享处理后的特征, 与 v8.8-B 的
   by_source 共享一致)。

相对 v8.8-B 的参数变化: 删除 9 处 OmniShift (每处 ~1.1K) + 新增 2 处
LargeKernelResidualShift (每处 ~0.8K), 净减约 8K; FLOPs 因移除 27 个
深度卷积而下降, 待实测。

## 五、实验编排 (三阶段, 不合并)

### 第一阶段: 推理期结构精简 (以 v8.8-B checkpoint 为基础, 不训练)

复用 `scripts/diag_shift_ablation.py` 的框架, 但按"整组置 Identity"组织:

| 实验 | 改动 | 验证 |
|---|---|---|
| A1 | N/M 的 Q-SM (shift_r/g) 整体置 Identity | M 路冗余结论 + N 路轻量化是否无损 |
| A2 | 三个头的 KV-SM (shift_k/v) 整体置 Identity | KV Shift 是否冗余 |
| A3 | N/M 的 cm_shift 整体置 Identity | CM 的任务相关性 |
| A4 | L 的 Q-SM 与 CM 只保留 5×5 (其余路置零, 保留原始 alpha_0) | 大核路径单独是否足够 |

A4 的实现细节: 不能把 5×5 分支的原始卷积权重当作完整 OmniShift 的等价替代,
需要按 alpha 加权合成等效单核后再替换, 脚本中逐处核对。

通过标准: A1/A2/A3 的 ΔPSNR ≥ −0.10 视为无损; A4 相对基线 ≥ −0.30
视为大核足够 (允许小幅损失, 因为它是新结构的第一近似)。

### 第二阶段: 实现 v8.8N

实现两个新模块 + TCA/头部的配置开关 (`shift_config: per_task`), 单测:
γ 零初始化的恒等起点、两步梯度解锁、三头配置差异、旧路径不受影响。

### 第三阶段: 30ep 训练

与 v8.8-B 同配置 (数据/优化器/seed/损失/SGRFv10/Encoder 不变),
唯一变量是 TCA 三个头的 Shift 形式。判据:

| 项 | 标准 (v8.8-B: 26.05 / 0.8432 / 0.3426) |
|---|---|
| PSNR | ≥ 25.95 (允许 −0.10, 换取结构与计算精简) |
| SSIM / LPIPS | ≥ 0.842 / ≤ 0.347 |
| 分支指标 | 相对误差与置零代价不明显退化 |
| 参数/延迟 | 参数净减, 延迟不升 |

若 PSNR 掉超过 0.15, 说明置零实验的"无损"不等于重训练的"可删"
(其余分支在重训练中未补偿), 回退到 v8.8-B 结构并记录该结论。

## 六、不采纳的外部建议 (记录理由)

- **C2 (Vision-RWKV 式逐通道混合)**: 固定方向位移弱于可学习 5×5,
  且 L 路 CM 的 0.75 dB 依赖表明需要真实邻域建模, 不实现;
- **KV2 (轻量 3×3 残差)**: 置零数据未证明 KV 需要额外卷积, 只作为
  A2 失败时的备选, 不进入默认结构;
- **固定低通滤波替代可学习 5×5**: alpha 偏恒等+大核不能证明学到的是
  低频平滑, 功能可能是局部对比度或结构补充, 可学习卷积更合适;
- **直接命名 v8.9**: 按用户裁决, 先建 `v8.8N` 验证精简无损, 再决定
  是否发展为正式版本。
