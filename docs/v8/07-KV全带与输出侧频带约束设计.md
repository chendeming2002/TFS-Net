# K/V 全带检索与输出侧频带约束

> 创建于 2026-10-19
> 前置结果: `02-实验计划.md` 第七节 (Cross RWKV Gate 15ep)
> 状态: 设计稿, 待决策

## 一、问题定位

两轮实验得到同一个结论: 更换空间头 (phase1 对 R1) 与更换整个任务查询机制
(U-Net 基线对 Cross RWKV Gate) 之后, N、M 两路的相对误差都停在 0.7 附近,
置零它们对最终 PSNR 没有代价。查询机制不是瓶颈。

剩下的差异集中在两处, 且都发生在注意力之前:

1. 每一路的 K/V 在进入 WKV 之前被固定滤波切掉了一部分内容 (N 取单帧中高频,
   L 取多帧大核低通, M 取单帧高频残差)。
2. 滤波发生在编码器特征上, 而编码器的通道已经混合了多个尺度, 不存在
   "某个通道对应某个图像频带" 的关系。因此这个滤波并不等价于图像域的频带分解。

第 1 点违反注意力的基本组织方式: K/V 是可供检索的内容池, 在检索之前把池子切掉一块,
注意力无法把它取回来。第 2 点说明切掉的那一块本来也不是物理意义上的频带。

本次改动的思路是: 让注意力在完整的特征上检索, 频带分工不放在检索入口, 而是放在
每一路输出的约束与监督上。

## 二、设计目标

- 三路 KV 都取完整特征, 不做任何固定滤波;
- 三路的分工由两样东西保证: 查询来源的差异 (已经存在), 以及输出侧对频带能量的约束;
- 任何一路都不会因为 "KV 被削掉" 而先天缺少它需要预测的内容;
- 改动可开关, 能与现有两个基线做单变量对照。

## 三、改动一: K/V 全带

### 3.1 具体修改

`TaskQueryAttention.forward`, 仅在 `q_mode == "cross_rwkv"` 时:

| 支路 | 原实现 | 改为 |
|------|------|------|
| N | `F1_single − lowpass(F1_single, 27)` | `F1_multi` |
| L | `lowpass(F1_multi, 27)`, 残差基 `F1_multi` | `F1_single`, 残差基 `F1_single` |
| M | `F1_single − lowpass(F1_single, 9)` | `F1_single` |

L 路的 K/V 与残差基都取中心帧, 而不是多帧聚合。理由见 3.2 节。

`kv_proj_*` 保持不变 (1×1 卷积 + LayerNorm), 它们的参数各不相同, 因此即使输入相同,
三路得到的 K/V 也落在不同的投影子空间。

查询保持不变: N 用 `F1_single − F1_multi`, L 用 `F1_multi`, M 用 `F1_single`。

### 3.2 为什么 L 路的 K/V 取中心帧

光照是当前帧自身的属性。多帧聚合把 5 帧的内容按权重平均, 对结构是好事, 对曝光不是:
若相邻帧的亮度与中心帧不同 (低光视频里很常见, 曝光在帧间缓慢漂移), 平均后的结果就是
一个中间曝光, 与要预测的中心帧光照图错位。L 路要输出的是中心帧的低频分量, 所以它的
K/V 应当来自中心帧。

R/G 仍取多帧聚合, 作用是提供"跨帧稳定的结构参照": 查询回答的是"这些稳定的结构在
当前帧上对应怎样的光照", 检索池则是当前帧的光照内容本身。这与论文里 R/G 来自
"当前帧 + 过去状态"、K/V 来自另一路输入的组织方式一致, 只是我们把两路都换成了
模型内部的两种帧组合。

### 3.3 一个需要记录的副作用

L 路的 R/G 与 K/V 来自两份不同的输入 (`F1_multi` 与 `F1_single`), 这一点比取消滤波
之前更接近论文的两路结构。N 路 (`F1_single − F1_multi` 对 `F1_multi`) 也是两路不同
来源。M 路的 R/G 与 K/V 都取中心帧, 属同源投影 —— 这是它"不引入跨帧运算"这一约定
的直接后果, 无法同时满足 "KV 全带" 与 "R/G 与 KV 不同源"。

接受的依据: Cross RWKV gate 的结构价值在于 R、G、K、V 四个独立投影与 R 之后的
归一化, 而不在于两路输入必须来自不同模态。我们本来也没有第二种模态。

若不接受, 替代做法是 KV 取 "全带特征 + 另一路特征的低成本拼接", 例如 N 的 KV 由
`F1_multi` 与 `(F1_single − F1_multi)` 各投影后相加, 但这样等于又把分工塞回 KV,
与本次设计的初衷相反。建议先按全带做。

## 四、改动二: 输出侧频带约束

频带分工移到输出侧之后, 有三种落地方式。三者的共同点是都作用在每一路的 RGB 输出
`Y_b` 上, 与 K/V 无关。

### 方案 A: 频带能量分布约束 (推荐)

对每一路输出 `Y_b` 与它自己的目标 `T_b`, 用与构造目标完全相同的滤波器把两者都拆成
低、中、高三段:

```
B_low(x)  = lowpass(x, 31)
B_mid(x)  = lowpass(x, 5) − lowpass(x, 31)
B_high(x) = x − lowpass(x, 5)
```

能量分布 (尺度无关, 只比较比例):

```
e_b = [ mean|B_low(Y_b)|, mean|B_mid(Y_b)|, mean|B_high(Y_b)| ]
t_b = [ mean|B_low(T_b)|, mean|B_mid(T_b)|, mean|B_high(T_b)| ]
```

两者各自归一化为和为 1, 损失为

```
L_band = Σ_b  || e_b/Σe_b − t_b/Σt_b ||_1
```

含义: 不规定每一路具体输出什么, 只规定它的能量应当落在哪些频段。L 路应当几乎全部
是低频, N 路应当集中在中高频, M 路应当集中在中频。目标一侧的比例由当前批次的目标
现算, 不是人为写死的常数。

同时加一条直流约束。N、M 的目标是零均值频带, 现在两路输出允许有直流分量, 这部分
实际上是在抢 L 路的活:

```
L_dc = mean(Y_N)² + mean(Y_M)²
```

推荐理由: 它不削减任何一方的表达能力, 只约束能量分配, 且在目标定义没有改动的前提下
直接可算。若某一路学得过头, 损失会把它的能量推回自己的频带, 而不是简单地把输出
截掉。

### 方案 B: 硬频带投影

把每一路的输出直接过固定带通:

```
Y_L ← B_low(Y_L),   Y_N ← B_mid(Y_N) + B_high(Y_N),   Y_M ← B_mid(Y_M) + B_high(Y_M)
```

优点: 分工是结构性的, 不可能违反。缺点: 三路的输出被限制在固定频带上, 高频的
N、M 两路无法修正 L 路残留的低频误差, 最终 PSNR 很可能下降。这与 "加性融合在权重
为 1 时精确等于 GT" 的性质冲突: 三路之和不再覆盖全频带时, 融合无法还原 GT 的
低频部分。

若采用, 必须同时把 L 路的权重固定为 1, 否则融合会抹掉低频。

### 方案 C: 可学习频带分解器 (单位分解约束)

每一路配一个可学习的 RGB 域频带滤波器 `K_b` (3×3 或 5×5 深度卷积, 初始化为该路的
目标频带), 并施加单位分解约束:

```
K_L + K_N + K_M = δ        (δ 为单位脉冲, 即三路之和为恒等)
```

输出为 `Y_b ← K_b(Y_b)`。约束保证三路频带没有遗漏也没有重叠, 融合结果在频带上
完整覆盖。

这个方案最接近 "把频带分工完全交给输出侧", 但它让分支有机会退化成三个固定滤波器,
从而绕开学习; 同时单位分解约束在卷积核上难以严格求解, 只能做软惩罚, 收敛行为不确定。
建议作为后续探索, 不放在第一轮。

### 建议

第一轮用方案 A。它改动小、可解释、不改变任何结构, 且能与现有基线直接比较。
方案 B 留作对照 (如果 A 的方向成立但没有足够效果, 说明软约束不够强);
方案 C 暂不实施。

## 五、实现位置与接口

新增文件 `models/golf_v7r/band_constraint.py`:

```
class BandEnergyLoss(nn.Module):
    """按图像频带比较每一路输出与自身目标的能量分布。"""
    def __init__(self, kernel_low=31, kernel_high=5, eps=1e-8)
    def forward(self, y_dict, target_dict) -> Tensor
```

在 `GolfNet_v8.forward` 中, 分支输出之后、融合之前调用, 结果放进返回字典的
`band_loss` 键。`GolfV7RLoss` 增加对应项, 权重由配置给出。滤波器直接复用
`datasets/branch_targets.py::lowpass`, 保证与目标构造的口径完全一致, 不另写一套。

`TaskQueryAttention` 增加参数 `kv_band_mode: str = "filtered"`, 取值
`"filtered"` (现行为) 或 `"full"`; `GolfNet_v8` 透传。旧配置不受影响。

配置项:

```
model:
  kv_band_mode: full
loss:
  w_band_share: 0.10
  w_band_dc: 0.05
  band_loss_start_epoch: 6     # 与分支目标 warmup 结束对齐
```

`band_loss_start_epoch` 的存在理由是: 前 5 轮模型还在建立基本重建能力, 此时约束
频带分布可能干扰收敛。与现有 `branch_warmup_epochs: 5` 对齐。

## 六、实验编排

三组, 逐级单变量:

| 编号 | KV | 频带损失 | 输出目录 | 回答的问题 |
|:--:|:--:|:--:|------|------|
| K1 | 全带 | 无 | `outputs/v8_fullkv_15ep` | 取消 KV 滤波本身是否有益 |
| K2 | 全带 | A | `outputs/v8_fullkv_bandloss_15ep` | 输出侧约束能否把 N、M 唤醒 |
| K3 | 滤波 (现状) | A | `outputs/v8_bandloss_15ep` | 输出侧约束是否独立于 KV 改动有效 |

K3 用于归因: 如果只有 K2 有效而 K3 无效, 说明两者必须配合; 如果 K3 也有效,
说明主要作用在输出约束, KV 改动可以回退。若时间只允许两组, 做 K1 与 K2。

## 七、判据

与现有两次实验同一套指标, 基线取 U-Net 15ep:

| 判据 | 基线 | 判为有效的条件 |
|------|------|------|
| 验证 PSNR | 24.12 dB | K1 不低于 23.9, K2 不低于 24.0 |
| N、M 相对自身目标的误差 | 0.73 / 0.71 | 至少一路降到 0.5 以下 |
| 置零 N 或 M 的代价 | −0.3 dB | 至少一路达到 −1.0 dB |
| 三路频带能量分布与目标的比例差 | 未测 | L 的路 1 范数差 < 0.3, N、M < 0.5 |
| 压暗下 L 的变化量 | 0.36 | 保持最大且不低于 0.30 |
| 加噪下 N 的变化量 | 0.62 (σ=0.05) | N 重新成为变化量最大的一路 |

最后两条是专属性检查。N 路的噪声专属性在上一轮已经失效, 这一轮如果仍然失效,
说明瓶颈既不在查询也不在 KV, 而在 "N 的目标与 M 的目标在中频上重叠 50%" 这个
目标构造本身。届时应当转向目标构造的消融, 不再在结构上迭代。

## 九、最终结果 (K1, 15 epoch, 2026-10-20 完成)

本次只实施改动一 (KV 全带, L 的 K/V 与残差基取中心帧), 未实施改动二。

### 9.1 验证指标

| 轮次 | 验证 PSNR | SSIM | LPIPS | 训练平均 loss |
|:--:|:--:|:--:|:--:|:--:|
| 5 | 23.05 dB | 0.8034 | 0.4333 | 0.5792 |
| 10 | **24.36 dB** | 0.8086 | 0.4101 | 0.5388 |
| 15 | 24.03 dB | 0.8102 | 0.4066 | 0.5140 |

最好的 checkpoint 在第 10 轮。第 15 轮的 PSNR 比第 10 轮低 0.33 dB, 但 SSIM 与
LPIPS 仍在改善 (0.8086 → 0.8102, 0.4101 → 0.4066), 训练损失也在持续下降。
这与前两次实验的走势不同: U-Net 基线到第 15 轮仍在涨, Cross RWKV Gate 到第 15 轮
已基本平台化。

### 9.2 与两个基线的对照

| 项 | U-Net 基线 | Cross RWKV (旧 KV) | K1 (全带 KV) |
|----|-----------:|-------------------:|-------------:|
| 验证 PSNR | 24.12 | 23.32 | 24.36 (ep10) |
| SSIM | 0.8078 | 0.8019 | 0.8086 |
| LPIPS | 0.4264 | 0.4265 | 0.4101 |
| 空间方差 N / M / L | 1.1e-3 / 7.3e-4 / 4.8e-2 | 1.19e-3 / 8.43e-4 / 5.22e-2 | 1.13e-3 / 8.47e-4 / 4.86e-2 |

| 置零代价 N / M / L (dB) | −0.26 / −0.33 / −15.9 | +0.02 / +0.02 / −15.2 | −0.62 / −0.34 / −16.8 |

K1 在验证 PSNR、LPIPS 与三路相对误差上都略好于 U-Net 基线, 是三次实验里最好的一个。
N 路的置零代价从 +0.02 dB 变为 −0.62 dB, 说明它重新被融合采用; M 路回到基线的 −0.34 dB

### 9.3 扰动响应

| 条件 | 最终 PSNR | 变化 N / L / M | 相对误差 N / L / M | 置零代价 dB N / L / M |
|:--|:--:|:--:|:--:|:--:|
| 干净输入 | 24.30 | — | 0.724 / 0.142 / 0.710 | −0.62 / −16.8 / −0.34 |
| 压暗 ×0.5 | 15.26 | 0.242 / **0.340** / 0.263 | 0.804 / 0.390 / 0.797 | −0.07 / −7.85 / −0.03 |
| 压暗 ×0.25 | 11.34 | 0.408 / **0.583** / 0.437 | 0.895 / 0.612 / 0.897 | +0.00 / −4.01 / +0.01 |
| 加噪 σ=0.02 | 23.42 | 0.195 / 0.069 / 0.192 | 0.769 / 0.162 / 0.759 | −0.54 / −15.9 / −0.31 |
| 加噪 σ=0.05 | 20.01 | **0.496** / 0.211 / 0.431 | 0.942 / 0.258 / 0.892 | −0.35 / −12.5 / −0.24 |
| 运动模糊 5 像素 | 24.26 | 0.062 / 0.012 / **0.064** | 0.727 / 0.141 / 0.712 | −0.65 / −16.8 / −0.36 |
| 运动模糊 9 像素 | 24.06 | 0.132 / 0.021 / **0.137** | 0.741 / 0.141 / 0.725 | −0.65 / −16.6 / −0.38 |

判读:

1. 压暗: L 路变化量最大 (0.340, 0.583), 与 "L 管光照" 一致, 且比前两轮更稳定。
2. 加噪 σ=0.05: N 路变化量 0.496, 重新成为三路最大 (基线 0.62, 旧 KV 0.43 / M 0.50)。
   噪声专属性第一次成立。
3. 运动模糊: M 略大于 N (0.064 对 0.062, 0.137 对 0.132), 方向正确但差距很小,
   与基线同量级。
4. 三路相对误差与置零代价在干净输入下都优于两个基线, 说明 KV 全带确实让 N、M 两路
   重新参与了重建。

### 9.4 结论

改动一是有效的: 三项主要指标 (PSNR 24.36、LPIPS 0.4101、N 的置零代价 −0.62 dB)
都超过了两个基线, 加噪条件下的噪声专属性也第一次成立。但 N、M 与自身目标的相对误差
仍在 0.71 附近, 只比全零输出好一点, 距离判据的 0.5 还有距离。

也就是说, KV 全带解决了 "两路完全不被融合采用" 的问题, 但没有解决 "两路学不深" 的问题。
按第七节的预设, 下一步应当转向目标构造的消融, 而不是继续在结构上迭代。
改动二 (输出侧频带约束) 是否还需要做, 取决于目标消融的结果。

## 十、v8.5 推理与训练加速 (2026-10-20)

两项改动, 都不改变模型的数学行为。

### 10.1 四方向扫描合并为一次算子调用

`models/modules/batched_wkv.py` 的 `batched_scan`, 把同一空间头的四个扫描方向堆到
batch 维, 一次调用算完。原来每个头调 4 次, 全模型 28 次; 现在 7 次。

为此改了三处内核细节:

1. 衰减与奖励参数改为按 (batch, channel) 寻址。原实现只读 `_u[_c]`, 不支持批量。
2. 网格改为把通道分组宽度往下调整到能整除 `B*C`。原实现用整除, 当 `B*C` 不能被
   16 整除时 (例如单方向、8 通道) 会算出 0 个线程块, 一个都不启动。
3. 去掉了核内的提前 `return`。它在 `__syncthreads()` 之前返回, 会造成块内线程分歧。

正确性: 新核与改动前的核在 C=16/32/128 上输出逐位相同 (最大差 0.000e+00);
批量调用与逐方向调用逐元素相同 (atol=0); 四个方向各自获得独立梯度, 不做跨方向求和。

收益: 推理 (batch 1, 256×256) 从 66 ms 降到 48 至 51 ms。训练 (batch 2) 无可见收益
(407 ms 对 408 ms), 原因是训练时 batch=2 已经让单次调用的并行度足够高, 而反向仍是
每方向一次调用, 合并只省掉了启动开销。所以这一项是**推理侧优化**。

### 10.2 OmniShift 推理自动重参数化

按 Restore-RWKV (`reference_repos/EvRWKV/egllie/models/Cross_Restore_RWKV.py:126`
的 `reparam_5x5`) 的做法, `OmniShift` 在 `eval()` 模式首次前向时把四个分支合并成
一个 5×5 深度卷积, 之后一直用合并后的卷积; 切回 `train()` 时丢弃合并结果, 保证权重
更新后不会用到过期卷积。训练仍走四分支, 所以训练行为完全不变。

等价性: 同一输入下四分支与合并卷积的最大差 8.2e-05 (由浮点求和顺序引起)。
推理延迟从约 51 ms 降到约 49 ms, 收益有限, 因为 OmniShift 本身的卷积占比不高。
