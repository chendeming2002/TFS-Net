# v8 命名对照 (术语表)

> 创建于 2026-10-19, 2026-10-20 按用户裁决定稿
> 用途: 把论文与口头使用的**部件名**与代码里的**符号名**一一钉死, 避免"同一个名字指两处、
> 同一处有两个名字"。本文档是命名口径的唯一来源, 后续文档与代码注释以本文为准。

## 一、部件名对照 (已定稿)

| 部件名 (论文/口头) | 代码符号 | 位置 | 实例数 | 在模型里的角色 |
|---|---|---|---|---|
| **FrameEncoder** | `FrameEncoder` | `models/golf/encoder.py` | 1 | 逐帧共享权重编码, 输出 3 尺度金字塔 |
| **TemporalAggregator** | `TemporalAggregator` | `models/golf_v7r/spatial_summary_unet.py` | 1 | F3→F2→F1 自上而下聚合; 产出多帧与单帧两路特征 |
| **TaskQueryAttention** | `TaskQueryAttention` | `models/golf_v7r/triple_query_tca_v9.py` | 1 | F1 尺度三源查询, 产出 F_N / F_L / F_M |
| **NBranch** | `NBranch` | `models/golf_v7r/branch_n_simple.py` | 1 | 噪声支路 → `Y_N` |
| **LBranch** | `LBranch` | `models/golf_v7r/branch_l_simple.py` | 1 | 光照支路 (Retinex) → `Y_L` |
| **MBranch** | `MBranch` | `models/golf_v7r/branch_m_simple.py` | 1 | 运动支路 (单帧模式) → `Y_M` |
| SGRF (v7.5 义) | `V7RFusion` | `models/golf_v7r/fusion_v7r.py` | 1 | 加性频带求和 + 局部精化 → `O_t` |

组装处统一在 `models/golf_v7r/golfnet_v8.py` 的 `GolfNet_v8.__init__`。

上表中的六个部件名已同时作为**类名**写入代码, 因此文档名与代码名不再分家。
每个旧类名保留为同一对象的别名 (例如 `BranchNSimple = NBranch`), 目的是让历史 run 的
加载脚本、旧文档与既有 checkpoint 无需改动即可继续工作。别名只在文件末尾出现一次,
标注为 "旧名别名", 新代码一律使用新名。

`V7RFusion` 是唯一的例外: 论文名 SGRF 与代码名不同, 原因是仓库里另有一个同名的旧类
`models/modules/igrf.py` 的 `SGRF` (两阶段串行复原, 不在 v8 路径上)。为避免两者混淆,
代码侧保留 `V7RFusion` 这个名字。

## 二、数据流 (用定稿名标注)

```
x [B,T,3,H,W]
  └─ FrameEncoder (逐帧, 共享权重, 每尺度 1 个 EncoderRWKVBlock 循环 2 次)
        → f1_seq [B,T,32,H,W], f2_seq [B,T,64,H/2,W/2], f3_seq [B,T,128,H/4,W/4]
  └─ TemporalAggregator
        ├─ 逐帧 EncoderRWKVBlock (在 F3 上) → f3_enc
        ├─ TemporalMatrixRWKVBlock (帧描述子 → 帧权重, 循环 2 次) → w [B,T]
        ├─ 加权求和 → F3_agg ──上采样+Conv 融合──→ F2_multi → F1_multi
        └─ 单帧旁路 → F1_single, F2_single (不跨帧)
  └─ TaskQueryAttention (F1 尺度)
        ├─ 3 个 QueryRWKVBlock (attn_N / attn_L / attn_M)
        └─ → F_N, F_L, F_M (各 [B,32,H,W]) + ortho_loss
  └─ NBranch(F_N) / LBranch(F_L, X_center) / MBranch(F_M) → Y_N, Y_L, Y_M (各 [B,3,H,W])
  └─ V7RFusion(Y_N, Y_L, Y_M, X_center) → O_t [B,3,H,W]
```

## 三、RWKV 块名对照

这三个名字是**功能名**, 用于论文与讨论; 代码里仍是类名。与第一节不同, 它们没有同步改名,
因为同一个功能名可能对应多个实现类, 强行统一会隐藏实现差异。

| 功能名 | 代码符号 | 位置 | 实例数 | 说明 |
|---|---|---|---|---|
| EncoderRWKVBlock | `RWKVEncoderBlock` | `models/golf_v7r/rwkv_encoder_block.py` | 4 | 同形状进出, 内部循环 `num_loops` 次 `SpatialRWKVHeadV8` |
| QueryRWKVBlock | `CrossRWKVHeadV8` | `models/golf_v7r/cross_rwkv_head_v8.py` | 3 | `SpatialRWKVHeadV8` 的子类; R/G 与 K/V 分别取不同来源 |
| TemporalMatrixRWKVBlock | `MatrixRWKVBlock` | `models/golf_v7r/matrix_rwkv.py` | 1 | 内含 `MatrixRWKVTimeMix`, 在帧维上建矩阵状态 |
| 空间扫描核心 (属实现细节) | `SpatialRWKVHeadV8` | `models/golf_v7r/spatial_rwkv_head_v8.py` | 4 直接 + 3 子类 | 上面两个块的公共底座 |
| WKV 扫描算子 (属实现细节) | `CudaBiWKV` / `TorchBiWKVSingleNorm` | `models/modules/cuda_wkv.py` | 28 | 每个空间头 4 个方向各 1 个 |

4 个 `EncoderRWKVBlock` 的分布:

| 位置 | 通道 | num_loops | 归属 |
|---|---|---|---|
| `encoder.scale1_blocks[0]` | 32 | 2 | FrameEncoder |
| `encoder.scale2_blocks[0]` | 64 | 2 | FrameEncoder |
| `encoder.scale3_blocks[0]` | 128 | 2 | FrameEncoder |
| `summary.frame_encoder` | 128 | 1 | TemporalAggregator |

28 个扫描的构成: 7 个空间头 (3 编码器 + 1 聚合器内 + 3 查询) × 4 个方向。
`TemporalMatrixRWKVBlock` 不产生扫描, 它是纯 PyTorch 的时序递归, 没有 CUDA 实现。

## 四、已知的同名与歧义 (保留现状, 使用时的注意点)

### 1. 部件 `FrameEncoder` 与成员 `summary.frame_encoder`

`TemporalAggregator` 内部有一个成员 `self.frame_encoder`, 它是单个 `EncoderRWKVBlock`,
不是 `FrameEncoder` 这个部件。两者一为部件、一为块, 只差大小写与下划线。

**现状**: 保留 `summary.frame_encoder` 不改。改名会改变 checkpoint 的 key, 使三次 15 轮
实验的 `best.pth` 无法直接加载。讨论时用全名区分: 部件说 "FrameEncoder", 成员说
"聚合器内的 `frame_encoder` 块"。

### 2. 功能名 `QueryRWKVBlock` 对应两个实现类

`TaskQueryAttention` 里的三个头是 `CrossRWKVHeadV8`, 当且仅当 `q_mode="cross_rwkv"`;
若配置为 `q_mode="receptance"`, 它们退化为基类 `SpatialRWKVHeadV8`。即一个功能名
对应两个类。

**现状**: `QueryRWKVBlock` 作为功能名保留, 指 "任务查询用的空间 RWKV 块", 在论文里
注明其实现为 Cross RWKV 双查询变体。15 轮实验用的是 `cross_rwkv`。

### 3. `TemporalAggregator` 不只做时序

它实际做三件事: 在 F3 上再跑一次空间编码; 用帧描述子加时序权重做跨帧加权; 以及 F3→F2→F1
的自上而下空间融合, 并旁路出单帧特征。

**现状**: `TemporalAggregator` 指整个部件, 不拆分。理由是它的对外接口只有
`F1_multi` / `F1_single` / `F2_single` 三个输出, 内部拆分属于实现细节。论文里需要说明
它同时承担空间聚合。

### 4. 旧 `SGRF` 与本项目的 SGRF 同名不同物

| 出处 | 代码 / 文档 | 含义 | 在 v8 路径上 |
|---|---|---|---|
| 旧 SGRF | `models/modules/igrf.py` 的 `SGRF` | 两阶段梯度隔离的复原: Stage A 提亮, Stage B 精炼。串行结构, 不是三分支并行 | 不在 |
| v7.5 SGRF | `docs/v7.5/` | 三分支融合部分定稿的名字 = 频带划分监督目标 + 加性加权融合 | 就是它 |

讨论时若只说 "SGRF", 必须先声明指哪一个。v8 代码里对应的是 `V7RFusion`。

另外需要记录: 早期 SGRF/IGRF 的**顺序级联拓扑** (去噪→去模糊→提亮) 在 v7r-v3 与 v8
上从未做过训练实验, 属尚未验证的候选方案。从那次分析里继承下来的是它的**梯度性质**
(加性偏导恒为 1, 三路梯度相等), 不是拓扑。

## 五、代码侧改动清单 (已完成)

| 项 | 改动 | 影响 |
|---|---|---|
| `SharedEncoder` | 类名改为 `FrameEncoder`, 保留别名 | 其他历史模型仍以旧名引用, 不受影响 |
| `SpatialSummaryUNet` | 类名改为 `TemporalAggregator`, 保留别名 | 同上 |
| `TripleQueryTCAv9` | 类名改为 `TaskQueryAttention`, 保留别名 | 同上; `triple_query_tca.py` 里的旧类 `TripleQueryTCA` 未动 |
| `BranchNSimple` / `BranchLSimple` / `BranchMSimple` | 类名改为 `NBranch` / `LBranch` / `MBranch`, 保留别名 | 同上 |
| `V7RFusion` | 不改 | SGRF 为论文名 |
| `CrossRWKVHeadV8` | 不改 | QueryRWKVBlock 为功能名 |
| `summary.frame_encoder` | 不改 | 保留 checkpoint 兼容性, 见第四节 1 |

原则: 部件名与代码名尽量一致; 功能名与实现类名允许分离, 但本文档必须能双向查找 ——
给定部件名知道去哪段代码, 给定代码符号知道它在论文里叫什么。
