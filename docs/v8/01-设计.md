# v8 设计: 多源噪声分割结构的整理与定稿

> 日期: 2026-10-15
> 前置: `../v7.5/` (三分支融合已定稿)、`../v7/03-v7r-v3-design.md` (全部实验与裁决)
> 本文档范围: RWKV 基线的整理与简化、Encoder 结构、RWKV-7 与 Value Residual 的引入

## 一、v8 要解决的问题

v7.5 已经定稿了三分支的**融合方式与监督目标** (频带划分 + 加性融合), 三路的分工也已确立。
v8 处理的是它上游的部分: **TCA 与编码器的 RWKV 实现**。

当前实现的问题不是"效果不好", 而是**来源混杂、缺少关键机制、无法说清创新点边界**:

| 问题 | 现状 |
|------|------|
| 来源混杂 | `BiWKV` 抄自 Vision-RWKV, 2D 四方向扫描 (`SpatialWKV2D`) 抄自 RSRWKV, 而 RSRWKV 不是 low-level vision 工作; 另有多处本地修补 (FastBiWKV / Mod1 / P3-hardening / R4-FIX) |
| 缺少核心机制 | 局部上下文 (Restore-RWKV 的 Omni-Shift) 缺失; Channel Mix 缺失。**已实施** (§三 A-impl+A-cm 合并版) |
| **M 路目标重叠** | 旧方案 S_M=0.5Q+0.2R 与 S_N=0.5Q+0.8R 共享中频带, corr=+0.93, 融合损失可用 N 覆盖 M 而无需 M 工作; 已改为 b 方案 (对齐残差, §三·补 b) |
| 只有 Spatial Mix | TCA 的空间注意力头没有 Channel Mix, 与 RWKV block 的经典两段式结构不符 |
| 无循环深度参数 | MatrixRWKV 用的是"堆 2 个 block", 没有 RWKV-7 那样的循环次数 $M$ |

## 二、先厘清: 当前实现的来源与缺口

### 2.1 两个独立的 RWKV 分支

必须分清, 它们服务于不同目的:

| 分支 | 文件 | 作用 | 层级 |
|------|------|------|------|
| 帧级时序 | `models/golf_v7r/matrix_rwkv.py` | 5 帧 token 序列上递推, 输出 `rwkv_ctx` | 帧级语义 |
| 空间注意力 | `models/golf_r4/tca_rwkv.py::RWKVSpatialHead` | 对特征图做 4 方向空间扫描 | 像素级 |

帧级分支的结构是完整的: `MatrixRWKVBlock = LayerNorm + TimeMix + LayerNorm + ChannelMix`,
TimeMix 是 RWKV-6 风格 (矩阵状态 $S \in \mathbb{R}^{d \times d}$ + 数据相关衰减),
ChannelMix 是 ReLU² MLP, 且带 LayerScale。**这一支基本符合经典结构, 少量修补。**

空间分支 (`RWKVSpatialHead`) 是问题所在。

### 2.2 空间分支的具体缺口

逐项对照 Vision-RWKV 与 Restore-RWKV 的应有形态:

| 项 | 当前实现 | Vision-RWKV / Restore-RWKV | 性质 |
|----|---------|---------------------------|------|
| 衰减 `w` | `-softplus(spatial_decay)`, 逐通道**可学习常量** | **同样**是逐通道可学习常量 (`self.spatial_decay = nn.Parameter(...)`, 见 `vrwkv.py:164/178/184`) | **相符** |
| 奖励 `u` | `spatial_first.clamp(-5,5)`, 逐通道可学习 | 逐通道可学习 (与当前一致) | 相符 |
| 局部上下文 | 无 (仅靠扫描顺序) | **Omni-Shift**: 四个方向的移位拼接 | **机制缺失** |
| Channel Mix | 无 | RWKV block 的标准组成 | **结构缺失** |
| 扫描策略 | 4 方向 (水平/垂直/主对角/反对角), 每方向独立 BiWKV | Vision-RWKV 用双向 1D 展平扫描 | 可保留, 属消融项 |
| 归一化 | `pre_norm` / `post_norm` (LayerNorm) | Vision-RWKV 用 LayerNorm | 相符 |
| 查询门控 | `out = sigmoid(q) * wkv` | Vision-RWKV 用 receptance `r` 门控 | **我们的创新 (见 §3.2)** |

来源标注: 文件头注释写明 "继承 pure_rwkv_sace.py 的 SpatialWKV2D + BiWKV",
而 `SpatialWKV2D` 的 docstring 写明 "RSRWKV 2D-WKV: 4方向"。
**RSRWKV 原论文并非针对 low-level vision 任务**, 其 2D 扫描设计动机与图像修复不同,
这部分应当重新评估, 不能默认照搬。

## 三、设计原则

### 3.1 以 Omni-Shift 为基础 (本地已有完整实现)

Restore-RWKV 是 RWKV-6 用于**医学图像修复**的工作, 与我们的任务同属 low-level vision。
它专门解决"RWKV 的时序 token shift 在图像上没有对应物"这个问题: 用多分支深度可分离卷积
构造具有局部上下文的输入表示。这正是低层视觉需要的归纳偏置。

**本地已有可用实现**, 不需要照论文重写:

| 位置 | 内容 |
|------|------|
| `reference_repos/EvRWKV/egllie/models/Cross_Restore_RWKV.py:103` | `class OmniShift` —— 完整实现 |

其形式是**可重参数化的多分支卷积**: `alpha[0]·x + alpha[1]·conv1x1 + alpha[2]·conv3x3
+ alpha[3]·conv5x5`, 全部为 depthwise; 推理阶段可合并成单个 5×5 卷积 (代码里已带
`reparam_5x5()`)。

> 注: v6 阶段的记录 (`docs/v6/TCA-RWKV/README.md:114`) 把这类模块称作 "EvRWKV 的 OmniShift",
> 并指出它比当前使用的 MVC-Shift 更强 (后者是并行局部增强, 与 WKV 递推无耦合)。
> Restore-RWKV 原论文用的是 3 方向移位拼接, EvRWKV 用的是上述多分支卷积形式,
> **两者取其一即可, 建议先用本地已有的 EvRWKV 版本**。

**做法**: 用 `OmniShift` 替代当前的"无局部上下文"状态 (当前 BiWKV 只接收 k/v, 没有任何
局部先验注入), 不自行发明新形式。

### 3.2 保留并强化"任务查询 Q"作为核心创新点

这是本工作相对所有 RWKV 变体的区别所在。经典 RWKV 是**无查询**的:

$$o_t = \frac{\sum_{m \le t} e^{-(t-m)w} \cdot e^{k_m} v_m}{\sum_{m \le t} e^{-(t-m)w} \cdot e^{k_m}}$$

输出只由 receptance $r_t$ 门控, 没有 query-key 匹配。我们的 TCA 引入了三路独立 Query,
与共享 KV 做匹配, 因此能把一个 KV 用三种方式读出——这正是三源分割得以实现的基础。

**为什么 Q 必须由我们引入**: 线性注意力/SSM 类方法中, Q 的角色本来就与 softmax 注意力
不同。需要梳理的对照:

| 方法 | 是否有 Q | Q 的作用 |
|------|:--:|------|
| softmax 注意力 | 有 | 决定对哪些位置分配权重 |
| 线性注意力 (Katharopoulos) | 有 | 同上, 但用核函数近似 |
| RWKV-4 ~ RWKV-7 | **无** | 只有 receptance 门控 $r$ |
| Mamba / Mamba-2 | 无 (有选择性机制) | 输入决定状态转移 |
| RetNet (GLA) | 有 | 门控衰减 + Q |

**候选形式** (需要实验决定):

- **A. 当前式**: `out = sigmoid(q) * wkv` —— Q 作门控。便宜, 但 Q 与 KV 不做匹配。
- **B. 二次读出式**: `out = softmax(q k^T) wkv` —— 让 Q 真正选择"读哪一段历史", 但引入
  二次复杂度, 与线性化目标矛盾 (可限制在窗口内)。
- **C. 低秩调制式**: 用 Q 调制 KV 的投影后再走扫描 —— 保持线性, 让 Q 影响"看什么"。
- **D. 双状态式**: 三路 Q 各自维护独立状态 $S_N, S_L, S_M$, 共享输入 KV —— 最贴近
  "同一输入、三种读出"的直觉, 参数量增加 3 倍。

### 3.3 为什么只有 Spatial Mix: 整理结论

这是需要说清楚的一个问题。**结论: 缺 Channel Mix 是历史沿革造成的, 没有技术理由。**

追查来源:

| 环节 | 情况 |
|------|------|
| 原始出处 | `models/modules/pure_rwkv_sace.py` 的 `SpatialWKV2D`, 其 docstring 写明 "RSRWKV 2D-WKV" |
| RSRWKV 的定位 | **不是 low-level vision 工作**。其 2D-WKV 是为图像分类设计的多方向扫描, 论文只讨论分类精度 |
| 引入时的取舍 | 当初只取了"扫描 + WKV 递推"这部分, Channel Mix 未一并引入 (v6 文档未见相关讨论) |
| 结果 | 当前空间头 = `pre_norm → QKV 投影 → 4方向扫描 → sigmoid(q) 门控 → proj_out → post_norm`, 没有 MLP |

对照经典结构: RWKV block 一直是 **Time Mix + Channel Mix** 两段式, 两者职责不同
—— Time Mix 做跨位置信息传递, Channel Mix 做逐位置跨通道变换。缺后者意味着这个模块
在文献意义上不是完整的 RWKV block。

**是否补回**: 应当补回。代价很小 (一个 2 层 MLP), 且这是"整理结构"的直接内容。
**但它是单变量实验**, 与 Omni-Shift 分开验证 (见实验计划 A 组)。

### 3.4 RWKV-7 与 Value Residual

**RWKV-7 的广义 delta 规则** (来自 `../v7/01-RWKV-mechanism-survey.md` §19):

$$S_t = S_{t-1}\big(\mathrm{diag}(w_t) - \hat{\kappa}_t^\top (a_t \odot \hat{\kappa}_t)\big) + v_t^\top \tilde{k}_t$$

相比 RWKV-6 的对角转移, RWKV-7 的转移矩阵是"对角 + 秩 1", 且引入了**向量值学习率** $a_t$
与解耦移除键。表达力更强, 但实现复杂度也更高。

**Value Residual** (来自 FEAT, 用于医学视频生成): 把**第一层**的 value 通过残差路径接入
**所有后续层**的 value。动机是深层网络容易丢失低层细节, 而修复任务恰好高度依赖低层细节。

**引入方式**: 先期探索**直接搬运原有实现, 不做小修小改**。理由是这两项机制的收益主要来自
其原始形式, 边引入边改会同时引入两个变量, 无法归因。

### 3.5 关于循环次数 M (回答一个具体问题)

**当前实现没有循环次数参数。** MatrixRWKV 用"堆 2 个 block"(`rwkv_blocks` 长度 2) 实现深度,
每个 block 有自己的参数; 而 Restore-RWKV 的 **Re-WKV** 是同一个模块**串行循环 M 次**
(计算量 ×M)。

两者不是同一回事:

| 形式 | 参数量 | 计算量 |
|------|:--:|:--:|
| 堆叠 N 个 block (当前) | ×N | ×N |
| Re-WKV 循环 M 次 | 不变 | ×M |

v6 阶段曾评估过 Re-WKV, 当时的结论是"串行循环 M 次, 计算量 ×M"因此未采纳
(`docs/v6/pureRWKV-Delta-plan.md:906`)。v8 阶段**也不引入 M** —— 它是深度方向的替代方案,
与 §二的机制缺口无关, 引入会同时改变参数量与计算量两个维度, 干扰归因。

## 三·补、BranchM 塌缩的复查结论 (2026-10-15 实测)

排查过程中我的判断经历了两次修正, 最终定位到与最初假设不同的原因, 记录如下。

| 阶段 | 假设 | 实测结果 |
|------|------|---------|
| 初次判断 (v7.5 §三) | upsample 输出尺度失控 (std 28.6 vs BranchN 0.012) 导致 GELU 死亡 | **对现象的描述准确, 但不是根因** |
| 修正一 | 在 `to_rgb` 前插 LayerNorm2d 补尺度 | 在**全新初始化**的模型上, 修复前后 upsample std 都是 0.9969, 正值占比 55.6% —— **M 路初始完全健康**, 尺度失配是训练中形成的, 不是静态缺陷 |
| 修正二 | 换 GELU 为 LeakyReLU (避免负半轴零梯度) | M 路 bstd 从 0.0001 升到 0.0018 (18×), 但**仍未复活** |

**决定性的梯度测量** (全新初始化模型, 逐项反传看 branch_M 的梯度范数):

| 仅用该项反传 | branch_M 参数梯度范数 |
|------|:--:|
| `l1` (融合输出) | **5.100e+00** |
| `branch_M` (自身目标) | 1.395e+00 |
| `branch_N` / `branch_L` | 0 (不经过 M 路, 符合预期) |

**结论: M 路既不缺梯度, 也不缺尺度, 而是缺少"必须学习的理由"。**

融合损失 `l1` 要求 $\sum_k w_k Y_k = GT$, 而三路目标中 **N 与 M 都含中频带 Q**
($S_M = 0.5Q + 0.2R$, $S_N = 0.5Q + 0.8R$)。只要 N 路把 Q 覆盖住, 融合输出就已经正确,
**M 路不需要贡献任何东西**。而 M 路自身的目标 $S_M$ 幅度极小 (实测 $|S_M| \approx 0.0145$,
仅为 $|S_L| = 0.4439$ 的 3.3%), 归一化后"输出零"的损失已经接近该指标下界
(零均值信号的 L1 在常数 0 处即达到约 1.000)。

⇒ **这是 v7.5 已知的"冗余"现象在频带层面的再现**, 但成因不同: v7.5 的冗余来自
"三路共享同一目标", 这里来自**"两路的目标重叠, 融合只需其一"**。

### 对 m 与 n 共享高频这一设计的重新评估

本轮实验表明, 共享的代价是**其中一路可以被完全忽略**。这与当初引入共享的理由
(噪声全频段、高频显著, 不应把 N 限制在最细高频) 并不矛盾 —— 问题的根源是
**共享比例让两路的目标高度相关**, 而非共享本身。

三条候选修正方向, 留待 v8 实验决定:

| 方向 | 做法 | 评估 |
|------|------|------|
| a | 让 $S_M$ 与 $S_N$ 正交化 (例如 M 取中频、N 取高频, 但用幅度归一化补偿 N 的频带过窄) | 回到 v7.5 已否定的严格划分, 需先解决 N 幅度过低的问题 |
| b | 给 M 路独立的、l1 无法替代的职责 (例如让 M 专门负责对齐残差, 其目标由 warp 与中心帧之差构造) | 与 §3.2 的任务查询 Q 天然契合 |
| c | 保留共享, 接受 M 路贡献低, 但把"某路可被忽略"作为已知性质写进论文 | 最省事, 但三分支的说法会打折扣 |

**v8 阶段暂不改动频带划分** (那属于 v7.5 已定稿的部分), 先把空间头与编码器整理干净;
上述三个方向待结构整理完成后再评估。

## 四、Encoder 的改造探索

当前编码器 (`models/golf/encoder.py::FrameEncoder`) 是 NAFNet block 构建的三尺度金字塔
(逐尺度 2 个 NAFBlock)。v8 探索**把编码器换成由 RWKV block 组成**。

动机: 编码器是唯一的非 RWKV 主干, 换成 RWKV 可以让整个模型在结构上统一。
但需要先回答两个问题:

1. **单帧处理下的空间 RWKV 是否够用**: 编码器是逐帧独立跑的, 没有时序信息,
   因此只能用空间扫描 (Omni-Shift + 双向扫描), 这正是 §3.1 要改的部分;
2. **参数量与显存**: encoder 当前 0.410M, 换成 RWKV block 后参数量会上升,
   需要控制在可接受范围。

**做法**: 保留 `FrameEncoder` 的接口 (输出三层金字塔 F1/F2/F3), 只把内部的 NAFBlock
替换为 RWKV block, 便于直接接入现有模型做对照。

## 五、关于扫描策略

十字方向、四方向等扫描顺序的消融**放入后续消融实验讨论, v8 阶段不投入精力**。
理由: 扫描策略是细节优化, 而 v8 要解决的是"机制缺失"与"结构不完整"这两个更根本的问题。
先补齐机制, 再谈扫描。

## 六·补·续、R1 完成后的归因结论 (2026-10-16)

R1 (residual 目标 + legacy 空间头) 已跑完 5 epoch, 验证集 PSNR 24.45 dB, 与 v7.5 定稿 (24.55)
和 Mfix (24.60) 同水平。用各 epoch 末的三路输出标准差 (bstd) 对比, 两个变量的作用已经分开:

| 运行 | 分支目标 | 空间头 | N 路 bstd (epoch 末) | M 路 bstd (epoch 末) |
|------|---------|--------|------|------|
| Mfix | band | legacy | 2.43 → 1.68 (全程活) | 2.06 → 5.51 (全程活) |
| **R1** | **residual** | **legacy** | **0.011 → 0.051 (活, 但比 band 低约 50 倍)** | **0.001 → 0.0007 (全程低)** |
| phase1 | residual | v8 | 0.014 → 0.0002 (500 步内塌) | 0.012 → 0.0002 (同) |

**两条归因, 各占一半:**

1. **N 路塌成常数图来自 v8 空间头。** 同样用 residual 目标, legacy 头的 R1 里 N 全程有活性
   (0.011–0.051, 时而冲到 0.10); 换成 v8 头的 phase1 在 500 步内就塌到 0.0002。
   目标相同、只有空间头不同, 归因落在空间头上。
2. **M 路低迷来自 residual 目标本身。** R1 换成 residual 目标后, M 从 band 版的 2–5
   掉到 0.0001–0.001, 低了三到四个数量级, 而空间头与 Mfix 相同 (都是 legacy)。

这与 §六·补 的机制解释一致: residual 目标的 N、M 两路都是纯零均值小纹理
(DC/std 分别 0.000 与 0.052), 归一化损失下"输出常数 0"就是该路损失的下界。

**据此确定 A 组编排**: v8 空间头已确认与 N 路塌缩有关, 因此 A 组必须做单变量
(A-impl 只加 OmniShift, A-cm 再加 Channel Mix), 不能合并跑。b 方案 (给 M 路分零均值残差)
正式废弃 —— 它既没有复活 M 路, 又压塌了 N 路。

### 本轮发现并修复的一个代码缺陷

写 `SpatialRWKVHeadV8` 的单测时发现: `channel_mix` 末层的零初始化被**覆盖**了。
`__init__` 里先做 `nn.init.zeros_(self.channel_mix[-1].weight)`, 随后调用的 `_init_weights()`
又对它做了 `kaiming_uniform_`, 结果末层根本不是零初始化, Channel Mix 从一开始就输出非零内容。

影响范围: phase1 探针用的就是这个带缺陷的版本。按设计, Channel Mix 应从"恒等残差"起步,
实际却从随机状态起步并在一开始就扰动表示; 但**这不改变本轮主结论** ——
N、M 两路塌成常数图是在 legacy 头上也能复现的现象 (R1 的早期 bstd 与 phase1 同向),
根因在分支目标而非这一处初始化。

修复: 把 `channel_mix` 的初始化统一收进 `_init_weights()`, 末层保持 `zeros_`, 不再被 kaiming 覆盖。
单测 `tests/test_spatial_rwkv_head_v8.py` 固化了这一要求 (末层权重和必须为 0)。

## 六·补、phase1 探针与 BranchM 修复的结果与裁决 (2026-10-16)

两个 5 epoch 探针都已跑完, 结论是 **b 方案没有复活 M 路, 反而让 N、M 两路一起塌成常数图**。
下表是三次运行在**相同的融合口径**下重新测量得到的数字, 不是训练脚本直接打印的原值。

| 运行 | 分支目标 | 空间头 | N 输出空间方差 | M 输出空间方差 | 去掉 N 的代价 | 去掉 M 的代价 |
|------|---------|--------|:--:|:--:|:--:|:--:|
| v7.5 定稿 | band | legacy | 7.6e-04 | 3.3e-05 | — | — |
| branchM_fix | band | legacy | 6.8e-04 | 5.5e-04 | +0.07 dB | +0.10 dB |
| phase1 | residual | v8 | **6.1e-18** | **4.5e-11** | -0.01 dB | +0.01 dB |

(空间方差是分支输出在单张图上逐像素的方差; 数值降到 1e-11 以下即"整张图几乎是同一个常数值"。
去掉某一路的代价用加性融合的正确口径计算: 直接把该路权重置零, 不做归一化。)

### 三个直接结论

第一, **branchM_fix 里的 N、M 两路虽然输出不为零, 但对最终结果没有贡献。**
去掉它们中任何一路, 最终 PSNR 的变化只有 +0.07 和 +0.10 dB, 落在噪声范围内;
只有去掉 L 路会掉 12.4 dB。也就是说整幅图的恢复几乎全部由光照分支承担,
另外两路是装饰性的。

第二, **phase1 把情况变差了。** N 路和 M 路的输出空间方差降到 1e-18 与 1e-11,
按数值精度这就是两张常数值图 (实测两路输出的标准差都是 0.0002, 而 L 路是 0.26)。
去掉它们, 最终 PSNR 分别变化 -0.01 与 +0.01 dB, 同样说明它们不参与恢复。

第三, **训练日志里 phase1 的损失从 0.23 涨到 0.73, 这不是发散, 是分支权重的预热斜坡。**
配置里 `branch_warmup_epochs=5`, 第 1 个 epoch 分支损失权重只有 0.06, 第 5 个 epoch 升到 0.30,
损失随之抬升。"损失上升"与"分支塌缩"是同一现象的两个侧面, 不是两次独立的故障。

### 为什么 b 方案会让 N、M 一起塌掉

b 方案的目标是"对齐残差", 三路目标的直流分量 (整幅图的平均亮度) 差别极大:

| 目标 | 平均绝对值 | 直流分量 | 标准差 | 直流/标准差 |
|------|:--:|:--:|:--:|:--:|
| S_L (光照) | 0.45 | 0.43 | 0.24 | 1.9 |
| S_N (噪声, residual) | 0.019 | -0.00000 | 0.043 | 0.000 |
| S_M (运动, residual) | 0.0099 | -0.00028 | 0.024 | 0.052 |

N、M 的目标**没有直流分量, 是纯零均值的小幅纹理**。而损失函数按每路目标的平均绝对值做归一化
(`scale = gt_b.abs().mean()`), 归一化后"分支输出恒为 0"这条最容易走到的解, 恰好就把该路的
归一化损失压到了下界 (对零均值信号, 常数 0 处的平均绝对误差等于该信号的尺度本身, 归一化后即 1.0)。
于是 N、M 两路**没有任何梯度压力去输出非零内容**, 唯一稳定的方向就是输出 0, 而 0 正是常数图。

L 路完全不同: 它的目标有强烈的直流分量, 输出的常数部分本身就是有效的亮度估计, 所以 L 路活了下来。

**这里有一个必须点明的归因限制: phase1 同时改了两个变量 —— 分支目标 (band→residual)
与空间头 (legacy→v8), 因此无法把塌缩归因到其中某一个。** 但有一条旁证指向目标而非空间头:
phase1 里三路共用同一个 v8 空间头, L 路用这个头活着, N、M 路用同一个头死掉,
说明差别来自**目标的性质 (有无直流分量)**, 而不是空间头本身的缺陷。

### 旧的消融数字作废

`outputs/v8_readout/v8_ablation.log` 里 phase1 那组"去掉 N 掉 10.95 dB、去掉 M 掉 7.57 dB"
的数字是**错误的**, 产生于消融脚本修正之前 (日志时间 09:27:06, 脚本修正时间 09:29:39)。
旧口径把加性融合的权重也做了归一化, 使剩余两路被放大 1.8 倍, 制造出约 -10 dB 的假衰减。
用正确口径重算, 同两条的代价分别是 -0.005 dB 与 +0.010 dB, 与 N、M 已是常数图这一事实一致。

### 下一步

1. **b 方案不再推进。** 它没有解决"某路可被忽略"的问题, 反而在数值上更彻底。
2. 若要继续追这个问题, 必须先做**单变量对照**把"目标"与"空间头"分开: 固定 legacy 头, 只换 residual 目标;
   以及固定 band 目标, 只换 v8 头。两次 5 epoch 运行即可判定。
3. **根本问题回到 v7.5 已记录的那条**: 只要某一路的目标不含其他两路不具备的成分 (这里是直流分量),
   融合损失就不需要它。任何"给某一路分一块频带"的方案都绕不开这一点;
   真正能保证不可替代的, 是该路负责的东西在数学上无法由其余两路拼出
   (b 方案当初的设计意图正是如此, 但实测显示零均值小目标在归一化损失下缺乏学习动力,
   这一层在本轮之前没有被识别)。
