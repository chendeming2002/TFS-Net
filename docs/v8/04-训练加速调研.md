> 日期: 2026-10-17

## 一、问题: 单步慢在哪

GPU 确认为 **NVIDIA GeForce RTX 4090 (24 GB)**, 因此不是"用错了卡"。

**先更正一个容易算错的数**: 训练日志里"每 epoch 耗时"是最可靠的时间来源。
本轮之前 5 epoch 的 run, 单个 epoch 约 77–101 分钟, 4629 步, 即 **约 1.07 秒/步**。
若用"首末时间戳差 ÷ 步数"去算会得到 5.5 秒/步, 那是因为每个 epoch 的步数计数会重置,
时间戳却跨了 5 个 epoch, 分母少算了 5 倍。

1.07 秒/步 对一个 3.75M 参数、batch=2、256×256 的模型仍然偏慢。诊断到的特征:

| 观察 | 数值 | 含义 |
|------|------|------|
| GPU 利用率 | 100% | 表面上"忙" |
| GPU 功耗 | 100–130 W / 450 W | 实际算力只用了三分之一不到 |
| 数据加载 (`num_workers=0`) | 413 ms/batch | 与 GPU 计算完全串行 |

**"利用率 100% 但功耗只有 1/4"是典型的"大量小算子串行、kernel 启动开销主导"**:
小 kernel 一个接一个启动, 每个都能让利用率显示为 100%, 但 SM 大部分时间在等下一个 kernel。

## 二、逐项排查 (都是实测, 不是推断)

| 项 | 做法 | 结果 | 结论 |
|:--:|------|------|------|
| 数据加载多进程 | `num_workers` = 0/2/4/6 | 413 / 450 / 507 / 547 ms/batch | 单进程最快 (数据集有帧级 LRU 缓存, worker 越多缓存越稀释)。**不是瓶颈** |
| 编码器逐帧循环合并成批量 | 串行 5 次 vs 合并成 1 次 | 24.2 ms vs 45.6 ms | 合并反而更慢 (小张量下批量不划算)。**不做** |
| TF32 | 前向 (b1, 256) | 253 → 221 ms | −13%, 零风险, **已启用** |
| AMP fp16 | 前向+反向 | 701 → 601 ms | −14%, 但本机对数值量级敏感, 暂不启用 |
| FastBiWKV chunk 1024→4096 | 单次扫描 | 18.2 → 16.5 ms | −9%, 数学等价 (固定权重下差 5.96e-08), **已启用** |
| **WKV 扫描换 CUDA 算子** | 前向 (b1, 256) | **109 → 25 ms** | **−77%, 见下** |

## 三、核心发现: 我们的双向 WKV 与官方参考不一致

### 3.1 发现过程

把 Vision-RWKV 的 CUDA 算子 (`reference_repos/Vision-RWKV/.../cuda/wkv_cuda.cu`) 编译后
与我们的 `FastBiWKV` 逐元素对比, 误差约 1.0 —— 不是精度问题, 是**两个不同的函数**。

读内核的输出行 (wkv_cuda.cu 第 89 行):

```cpp
y[ii] = (c * e1 + a * e2 + e3 * v[ii]) / (d * e1 + b * e2 + e3 + EPS);
```

其中 `c, d` 是前向累加量, `a, b` 是后向累加量, `e3 = exp(u + k[ii])` 是自项。
**前向与后向的贡献进同一个分子、同一个分母, 只做一次相除。**

我们的 `BiWKV.forward` (models/modules/pure_rwkv_sace.py:106-108):

```python
wkv_fwd = self._scan_cumsum(...)          # 各自归一化
wkv_bwd = self._scan_cumsum(...)
return (wkv_fwd + wkv_bwd) * 0.5          # 两个比值再平均
```

**两种写法数学上不等价**: 先分别相除再平均 ≠ 先合并分子分母再相除。

### 3.2 判定 (哪一边是官方定义)

用暴力参考 (逐位置、逐 j 精确计算) 在数值稳定的衰减下对比:

| 候选公式 | 与官方核的相对误差 |
|---------|:--:|
| 单归一化双向 (前向 + 后向 + 自项进同一分子分母) | **6.7e-03** |
| 双比值平均 (我们的实现) | **8.7** |

⇒ **官方核采用单归一化双向; 我们的实现与参考不符。**

另有两处旁证:

1. Vision-RWKV 的 `forward` (vrwkv.py:219) **只调用一次 `RUN_CUDA`, 没有 flip、没有平均**。
2. 官方另有专门的 `bi_wkv_kernel.cu` (双向核), 其输出行与上式完全相同。

结论: **我们的双向组合方式是自行写成"两比值平均"的, 与 Vision-RWKV / Restore-RWKV 系的
参考实现不一致。** 这不是加速问题, 是一处实现与参考的偏差。

## 四、修正与接入

### 4.1 新增模块

`models/modules/cuda_wkv.py`:

| 类 | 作用 |
|----|------|
| `CudaBiWKV` | 官方定义 (单归一化双向), 调用 CUDA 算子, **单次调用**即得双向结果 |
| `TorchBiWKVSingleNorm` | 同定义的纯 PyTorch 版本, 仅在无 CUDA 工具链时回退 |
| `make_wkv()` | 优先 CUDA, 不可用时自动回退 |

已验证三者一致 (固定参数、L=32、C=4):

| 对比 | 相对误差 |
|------|:--:|
| CUDA 版 vs 暴力参考 | 3.9e-07 |
| PyTorch 回退版 vs 暴力参考 | 1.6e-07 |
| CUDA 版 vs 回退版 | 3.3e-07 |

### 4.2 公式映射 (两处容易写错的地方, 都已实测验证)

官方核的公式是:

```
y_t = [ Σ_{j≠t} exp(k_j − w_kernel·|t−j|) v_j + exp(u_kernel + k_t) v_t ]
    / [ Σ_{j≠t} exp(k_j − w_kernel·|t−j|)       + exp(u_kernel + k_t)     ]
```

- **衰减符号**: 核内写作 `exp(−w_kernel·距离)`, 要求 `w_kernel > 0`;
  我们的 `w = −softplus(spatial_decay) < 0`, 衰减因子为 `exp(w/T·距离)`,
  因此必须传 `w_kernel = −w/T`。直接传 `w/T` 会让指数发散 (实测误差 1.0)。
- **奖励项**: 核用 `exp(u_kernel + k)`, 我们等价于 `exp(u/T)·exp(k)`, 故 `u_kernel = u/T`。

### 4.3 小坑

- 参考的 `wkv_op.cpp` 里除了 `PYBIND11_MODULE` 还有一段 `TORCH_LIBRARY(wkv, ...)`。
  同一进程内重复加载同命名空间会直接报错。本项目只用 `PYBIND11_MODULE`, 已删除该段。
- 编译环境: 系统默认 `gcc` 是 7.5, torch 2.2 要求 ≥ 9; `nvcc` 不在 PATH。
  可用的组合是 `/usr/local/cuda` (nvcc 11.8, 与 torch 的 CUDA 11.8 一致) + `/usr/bin/gcc-9`,
  并且要把 `$CONDA_PREFIX/bin` 加进 PATH (否则找不到 ninja)。

## 五、实测收益

| 配置 | 前向 (batch=1, 256×256) | 前向+反向 | 单步 (batch=2) |
|------|:--:|:--:|:--:|
| `wkv_mode="legacy"` | 109 ms | — | 约 1.07 s |
| `wkv_mode="single_norm"` | 25 ms | 371 ms | 待正式训练确认 |

**前向 4.4 倍、端到端单步约 9.5 倍**(后者还包含了 TF32 与编码器侧同样切到 CUDA 版的效果)。

编码器的 RWKV block 也必须透传 `wkv_mode`, 否则它会退回 PyTorch 版:
未透传时 encoder 5 帧要 1611 ms, 透传后 119 ms。

## 六、开关注入方式

| 开关 | 默认 | 说明 |
|------|:--:|------|
| `wkv_mode` | `"legacy"` | `"single_norm"` 启用官方定义 + CUDA 算子 |
| `torch.backends.*.allow_tf32` | 训练脚本中设为 True | 无需配置, 默认启用 |
| `dataset.num_workers` | 配置项 | 合并实验用 6 |

`wkv_mode` 一路透传: `GolfNet_v7r_v3` → `TripleQueryTCA` / `SharedEncoder` → 各空间头。

## 七、对后续实验的影响

1. **已跑完的 run (Mfix / R1 / phase1 / B1 前 900 步) 用的是旧的双向定义**,
   与之后启用 `single_norm` 的 run 不再是同一个函数。因此**不能跨定义比较 PSNR**,
   只能比较同一模式内部的机制指标。
2. 合并实验 (`combined_B1M1M2M3A.yaml`) 同时启用 `single_norm`。它同时改动了多处结构,
   本身不能用于归因; 它的用途是给出"合并版"的整体表现, 作为后续逐项拆解的起点。
3. 若后续要做单变量消融, `wkv_mode` 应作为**固定项** (全部用 `single_norm`), 不再单独拆。

## 八、没做的事

| 项 | 原因 |
|----|------|
| AMP fp16 | 只省 14%, 而本机对数值量级敏感 (曾因 1e-5 差异放弃逐位复现), 风险收益不划算 |
| 自行编写 CUDA kernel 融合 chunk 循环 | 官方算子的作用就是把整条扫描塌缩成单个 kernel, 已满足需求 |
| 多卡 / 多进程并行训练 | 单卡 24 GB, 并发会 OOM (已有记录); 当前加速已足够 |
