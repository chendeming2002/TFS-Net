# TFS-Net v4.3 Design — Hybrid lit_up_map + Bounded Brightening

## 1. v4.2 Training Failure Diagnosis

### 1.1 现象

| Metric | v4.1 | v4.2 |
|--------|------|------|
| Epoch 1 loss drop | 4.8% | **0.20%** |
| Epoch 2 loss trend | 下降 | **上升** |
| Epoch 2 inter trend | 下降 | **上升** |

v4.2 比 v4.1 训练效果更差，loss 几乎不下降，epoch 2 甚至反弹。

### 1.2 根因分析：clamp × exp 梯度死区

v4.2 BrightenStage 核心计算：
```python
lit_up_map = exp(log(lit_up_map_raw) + delta)   # lit_up_map 可达 3~7
res_t = clamp(img_dark * lit_up_map, 0, 1)       # 大量像素被截断为 1
```

**问题链**：
1. L_ratio 初始值范围 [0.5, 8.0]，lit_up_refine 从零启动，所以 lit_up_map_raw ≈ L_ratio ≈ 2~5
2. BrightenStage 的 delta 初始近零，lit_up_map ≈ lit_up_map_raw ≈ 2~5
3. img_dark 值约 0.1~0.4（低光图像），乘积 img_dark × lit_up_map ≈ 0.2~2.0
4. 乘积 > 1 的像素被 clamp 到 1 → **梯度为零**（clamp 在 >1 区间导数为 0）
5. 梯度仅来自乘积 < 1 的像素（最暗区域），但这些区域 img_dark 很小
6. ∂L/∂lit_up_map = img_dark × (res_t - GT) → 暗区梯度幅值极小

**数值验证**：
- lit_up_map mean=1.18, range=[0.44, 7.42]（smoke test 数据）
- 7.42 意味着部分像素提亮 7.42 倍，img=0.15 × 7.42 = 1.11 → 被截断
- 被截断像素的梯度完全丢失，模型无法学习正确的提亮强度

### 1.3 与 v4.1 对比

v4.1 用加法残差 `img + delta`：
- delta 通常在 [-0.1, 0.1] 范围，很少有像素超出 [0, 1]
- 即使超出，只有极端像素被截断，大部分梯度正常传播
- 所以 v4.1 loss 能正常下降

v4.2 用乘法 `img × lit_up_map`：
- lit_up_map 在 [1, 5] 范围，大量像素乘积 > 1 被截断
- 梯度死区比例远高于 v4.1
- 这是乘法提亮 + 硬截断的根本矛盾

## 2. v4.3 设计方案

### 2.1 核心改进

**改进 1：有界提亮图（Bounded lit_up_map）**

```python
# v4.2 (无界，导致 clamp 死区)
lit_up_map = exp(log(lit_up_map_raw) + delta)    # range: (0, +∞)

# v4.3 (有界，避免 clamp 死区)
lit_up_map = 1.0 + max_bright * sigmoid(raw_feat)  # range: [1, 1+max_bright]
# 例如 max_bright=4 → lit_up_map ∈ [1, 5]
```

原理：sigmoid 将输出限制在 [0, 1]，乘以 max_bright 后提亮倍率上限可控。
最暗像素 img=0.05 × 5 = 0.25 < 1，不会被截断。
最亮像素 img=0.3 × 5 = 1.5 > 1，仍有少量截断但远少于 v4.2。

**改进 2：混合 lit_up_map 估计（Hybrid Estimation）**

```python
# v4.2 (纯图像空间，缺乏上下文)
lit_up_map_raw = L_ratio + lit_up_refine(L_ratio)    # 3ch → 3ch

# v4.3 (混合：L_ratio 物理锚定 + 64ch 特征空间修正)
ratio_feat = self.ratio_proj(L_ratio)                 # 3ch → 64ch
f_illum_feat = self.feat_refine(ratio_feat)           # 64ch → 64ch
lit_up_delta = self.lit_up_proj(f_illum_feat)         # 64ch → 3ch 特征修正量
lit_up_feat = L_ratio + lit_up_delta                  # 物理锚定 + 特征修正
lit_up_map_raw = 1.0 + max_bright * sigmoid(lit_up_feat)  # 有界提亮图
```

优势：
- L_ratio 提供物理锚定，初始 lit_up_map ≈ 1 + max_bright × sigmoid(L_ratio)，接近合理提亮估计
- f_illum_feat 的 64ch 空间上下文（阴影边界、色温）通过 lit_up_proj 修正提亮图
- sigmoid 保证输出有界，从根源消除 clamp 梯度死区

**改进 3：BrightenStage 有界 delta 修正**

```python
# v4.2 (无界 delta，可能进一步放大 lit_up_map)
lit_up_map = exp(log(lit_up_map_raw) + delta)

# v4.3 (有界 delta，提亮调整限制在 ±50%)
lit_up_map = lit_up_map_raw * (1.0 + tanh(delta) * 0.5)  # 调整范围: [0.5×, 1.5×]
```

原理：tanh(delta) ∈ [-1, 1]，乘以 0.5 后调整范围 ±50%。
lit_up_map 最终范围: [0.5, 5] × [0.5, 1.5] = [0.25, 7.5]，但实际很少有极端组合。
如果 lit_up_map_raw ≈ 2~3，调整后 ≈ 1.0~4.5，img=0.2 × 4.5 = 0.9 < 1，截断极少。

**改进 4：保留 .detach() 梯度隔离**

与 v4.2 一致，img_s1.detach() 和 img_s2.detach() 截断跨阶段梯度。

### 2.2 IFPN v4.3

```python
class IFPN(nn.Module):
    def __init__(self, ..., max_bright=4.0):
        ...
        self.ratio_proj = nn.Conv2d(img_channels, fused_channels, 1)
        self.feat_refine = nn.Sequential(
            ConvBlock(fused_channels, fused_channels, 3, 1, 1, act=True),
            ConvBlock(fused_channels, fused_channels, 1, 1, 0, act=False),
        )
        # v4.3: 特征空间→提亮修正量（混合方案核心）
        self.lit_up_proj = nn.Conv2d(fused_channels, img_channels, 1)
        self.max_bright = max_bright

    def forward(self, ...):
        ...
        L_ratio = ...  # L_ref / L_t, clamp(0.5, 8.0)
        ratio_feat = self.ratio_proj(L_ratio)
        f_illum_feat = self.feat_refine(ratio_feat)

        # 混合: L_ratio 物理锚定 + 特征修正 → 有界提亮图
        lit_up_delta = self.lit_up_proj(f_illum_feat)         # 64ch → 3ch
        lit_up_feat = L_ratio + lit_up_delta                  # 锚定 + 修正
        lit_up_map_raw = 1.0 + self.max_bright * torch.sigmoid(lit_up_feat)

        return {
            "lit_up_map_raw": lit_up_map_raw,
            "f_illum_feat":   f_illum_feat,
            ...
        }
```

参数变化：lit_up_refine(3→16→3 ≈ 576) → lit_up_proj(64→3 ≈ 195) — 更少参数，更强表达

### 2.3 IGRF v4.3 BrightenStage

```python
class BrightenStage(nn.Module):
    def __init__(self, channels, img_channels=3, max_delta=0.5):
        ...
        self.feat_proj = nn.Conv2d(channels, img_channels, 3, 1, 1)
        self.img_proj = nn.Conv2d(img_channels, img_channels, 3, 1, 1)
        self.delta_refine = nn.Sequential(
            nn.Conv2d(img_channels * 2, img_channels, 1, 1, 0),
            nn.GELU(),
            ResBlock(img_channels),
            nn.Conv2d(img_channels, img_channels, 3, 1, 1),
        )
        self.max_delta = max_delta

    def forward(self, lit_up_map_raw, f_illum_feat, img_dark):
        feat_cond = self.feat_proj(f_illum_feat)
        img_cond = self.img_proj(img_dark)
        delta = self.delta_refine(torch.cat([feat_cond, img_cond], dim=1))

        # 有界 delta: tanh 限制调整范围在 ±max_delta
        lit_up_map = lit_up_map_raw * (1.0 + torch.tanh(delta) * self.max_delta)
        lit_up_map = lit_up_map.clamp(min=0.5)

        res_t = torch.clamp(img_dark * lit_up_map, 0.0, 1.0)
        return res_t, lit_up_map
```

### 2.4 梯度分析

v4.3 的梯度路径：
```
∂res_t/∂(tanh(delta)) = img_dark × lit_up_map_raw × max_delta × sech²(delta)
```
- sech²(delta) ∈ (0, 1]，最大值在 delta=0 时取 1
- img_dark × lit_up_map_raw 是提亮后的值（≈ res_t），不像 v4.2 依赖未提亮的 img_dark
- 梯度幅值与 res_t 成正比（接近 GT 的像素梯度大），而不是与 img_dark 成正比（暗区梯度小）

v4.2 vs v4.3 梯度对比：
```
v4.2: ∂L/∂lit_up_map = img_dark × (...)    ← 暗区梯度极小
v4.3: ∂L/∂(tanh(delta)) = img_dark × lit_up_map_raw × max_delta × sech² × (...)
      ≈ res_t_raw × (...)                   ← 与提亮后值成正比
```

由于 sigmoid 有界化减少了 clamp 截断比例，更多像素的梯度能正常传播。

### 2.5 预期效果

| 问题 | v4.2 | v4.3 |
|------|------|------|
| clamp 梯度死区 | 大量像素 >1 被截断 | sigmoid 有界，极少截断 |
| lit_up_map 范围 | [0.44, 7.42] 无界 | [1.0, 5.0] 有界 |
| 梯度信号 | 仅暗区有梯度（弱） | 提亮后值成正比（强） |
| 物理锚定 | L_ratio 残差 | L_ratio + 特征修正 |
| 特征空间信息 | 未利用 | 64ch 特征参与提亮估计 |

## 3. Gradient Flow Fix: Remove .detach()

### 3.1 问题诊断

训练 4 epochs 后 loss 仅下降 1.5%（0.52 → 0.51），几乎完全平台期。

**根因**：BrightenStage 调用时对 img_s2 使用 .detach()，导致 L_recon 梯度无法流经 NDPN/MRPN。

```python
# 原始代码（梯度阻断）
res_t, lit_up_map = self.brighten(lit_up_map_raw, f_illum_feat, img_s2.detach())
#                                                          ^^^^^^^^^^^^
#                                          .detach() 切断梯度到 img_s2
```

**梯度流分析**：

| Loss 项 | 计算 | NDPN/MRPN 是否获得梯度 |
|---------|------|----------------------|
| L_recon | Charb(res_t, GT) | ❌ 被 .detach() 阻断 |
| L_inter | Charb(img_s2 × lit_up_map, GT) | ✅ 可以到达 |

L_recon 包含主要的像素/频域/感知损失，是模型学习的主要信号。.detach() 导致 NDPN（降噪）和 MRPN（去模糊）只能从 L_inter 获得梯度，而 L_inter 是间接监督（通过 lit_up_map 放大），信号太弱无法驱动学习。

### 3.2 修复方案

移除 img_s2 的 .detach()，让 L_recon 梯度直接流经整个级联：

```python
# 修复后（梯度流通）
res_t, lit_up_map = self.brighten(lit_up_map_raw, f_illum_feat, img_s2)
#                                                           ^^^^^^
#                                          无 .detach()，梯度可流到 NDPN/MRPN
```

**梯度路径**：
```
L_recon → res_t = img_s2 × lit_up_map
        → ∂res_t/∂img_s2 = lit_up_map
        → ∂img_s2/∂(NDPN/MRPN params) = 有梯度
```

### 3.3 设计决策说明

| 方面 | 原始设计 (.detach()) | 修复后 (无 .detach()) |
|------|---------------------|---------------------|
| BrightenStage 隔离 | ✅ 完全隔离 | ⚠️ 梯度会传回前序阶段 |
| NDPN/MRPN 训练 | ❌ 只有 L_inter | ✅ L_recon + L_inter |
| 预期收敛性 | 平台期 | 正常收敛 |

.remove .detach() 后，BrightenStage 的梯度会传回 NDPN/MRPN，这是正确的行为——降噪和去模糊应该通过最终重建损失（L_recon）来优化，而不仅仅是中间监督（L_inter）。
