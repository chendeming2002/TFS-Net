# TFS-Net v3 架构设计缺陷分析

## 一、背景

本文档记录对 TFS-Net v3 论文设计中存在的根本性问题的分析。这些问题无法通过简单的超参数调整解决，但可通过 v3.2 的训练策略改进（辅助损失、soft-median 等）**缓解**。

测试环境：TFS-Net v3.1（已修复 IGRF 重建头 + 归一化加权 + 4 级编码器），总参数 1.264M。

---

## 二、核心问题：三源分支梯度饥饿

### 2.1 量化数据

通过 L1 loss 反向传播后各模块的平均梯度范数（越小越难学习）：

| 模块 | 平均梯度范数 | 相对IGRF比率 |
|------|------------|-------------|
| igrf | 0.0765 | 1.00x (基准) |
| encoder | 0.0476 | 0.62x |
| tfsi | 0.0400 | 0.52x |
| mrpn | 0.0058 | **0.075x** |
| ndpn | 0.0021 | **0.028x** |
| ifpn | 0.0011 | **0.015x** |
| sace | 0.0009 | **0.011x** |

**结论**：IFPN/NDPN/MRPN/SACE 获得的梯度信号仅为 IGRF 的 **1%~8%**，处于有效学习的下限以下。

### 2.2 原因分析

#### 原因 1：归一化加权的固有梯度衰减

IGRF 的融合公式：

```
w_total = s_illum + s_noise + s_motion + 1.0
f_fused = (s_illum/w_total) * f_illum + (s_noise/w_total) * f_noise + (s_motion/w_total) * f_motion + (1/w_total) * f_base
```

初始化时（s_* 接近 0.3~0.5）：
- w_total ≈ 2.2
- w_base = 1/2.2 ≈ **0.46**（base 路径）
- w_illum ≈ 0.22, w_noise ≈ 0.12, w_motion ≈ 0.19

梯度 `∂L/∂f_branch = (s_branch / w_total) * ∂L/∂f_fused`，分支获得的梯度被 s/w_total 因子（0.12~0.22）衰减。

**根本矛盾**：归一化加权保证了输出稳定性（权重和为 1），但同时必然导致分支梯度衰减。base 权重占比最大，梯度优势使得 encoder→IGRF 成为唯一有效路径，三源分支形同虚设。

#### 原因 2：无分支直接监督

论文设计中：
- s_illum 仅通过 `L_illum`（edge-aware smooth）得到间接监督
- **s_noise 和 s_motion 完全无任何直接损失**
- 三源分支输出仅通过 IGRF 归一化加权后参与最终重建

这意味着分支必须通过极其间接的梯度路径学习：
```
L_total → ∂res_t → ∂f_fused → (s_branch/w_total) → ∂f_branch_out → ∂branch_params
```

多层链式乘积导致梯度消失。

#### 原因 3：Median 操作的梯度稀疏性

SACE 中 `mu_t_clean = feats.median(dim=1).values` 的梯度特性：
- 对 T=5 帧，每个空间位置只有 1 帧（被选为中位值的那帧）获得非零梯度
- 80% 的帧在每个位置的梯度为 0
- LFF 模块只有极少参数（2.4K），本身容量有限，又被稀疏梯度进一步削弱

### 2.3 设计级后果

1. **分支退化为恒等映射**：梯度不足 → 分支参数近零更新 → 分支输出≈输入 → IGRF 实质上只用 base 路径
2. **容量浪费**：IFPN(55K) + NDPN(78K) + MRPN(92K) + SACE(25K) 共 250K 参数（占比 20%）几乎无用
3. **平台期不可避免**：仅靠 encoder(557K)+IGRF(297K) 的 854K 参数做全部重建工作，容量有限

## 三、次要问题

### 3.1 三源分支无特化机制

三个分支（IFPN/NDPN/MRPN）的初始化状态几乎相同：
- 都从对齐特征开始
- 都输出相同形状的 (B, C_f, H, W) 特征
- 初始输出都接近输入的恒等变换

**没有任何显式机制**强制它们分别学习光照/噪声/运动的不同语义。分工完全依赖 s_* 的间接梯度引导，而这个引导信号极弱（见 2.2）。

### 3.2 IFPN L_ratio 数值不稳定

```python
L_ratio = L_ref / (L_t.abs() + eps)  # eps=1e-3
```

当 L_t 接近 0（低光区域常见），L_ratio 可达 ±25 甚至更大。这导致：
- `F_t * (1 + ratio_feat)` 中的乘性调制产生极大值
- 梯度爆炸或 NaN
- IFPN 训练极不稳定

### 3.3 Motion weights 初始恒等

MRPN 的 `weight_conv` 零初始化导致：
- 所有邻帧权重 = sigmoid(0) = 0.5
- 中心帧权重 = 1.0
- 归一化后：motion_weights 全部 = 1/(T-1+2) ≈ 0.167

即 MRPN 初始状态是所有帧简单平均，无任何运动选择性。需要大量梯度才能打破这个对称性。

## 四、v3.2 缓解方案

| 问题 | 缓解措施 | 预期效果 |
|------|---------|---------|
| 分支梯度饥饿 | 辅助分支损失 (λ_aux=0.2) | 给每个分支直接监督，梯度提升 10-50x |
| Median 梯度稀疏 | Soft-median (τ=0.1) | 所有帧获得梯度，SACE 梯度提升 5x+ |
| L_ratio 爆炸 | clamp(-4, 4) | 消除极端值，稳定训练 |
| L1 收敛慢 | Charbonnier loss | 零点附近梯度更平滑 |
| 缺少结构约束 | SSIM loss (λ=0.2) | 提供结构感知梯度 |
| 初期学习率过大 | LR warmup (5 epochs) | 保护初始化 |
| 梯度不稳定 | grad_clip=1.0 | 防止极端更新 |

**注意**：这些措施**缓解**但**不根治**问题。根治方案需要重新设计融合机制（如移除归一化加权中的 base 项、改为残差式融合、或给分支单独的重建头），但这会偏离论文原理。

## 五、未来潜在改进方向（超出当前 scope）

1. **残差式融合**：`f_fused = f_base + sum(s_i * (f_branch_i - f_base))`，确保分支只需学习增量
2. **分支 decoder heads**：每个分支各自重建，最后加权融合 RGB 输出（而非特征）
3. **对比损失特化**：用对比学习强制三分支提取不同语义
4. **渐进式训练**：先冻结分支仅训练 encoder+IGRF，再解冻分支微调
5. **可学习的 base 权重**：替换固定的 1.0，让 base 权重也可学习下降
