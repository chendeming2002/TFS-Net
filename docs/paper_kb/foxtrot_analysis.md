### 1.2 三指标趋势解读（关键）

**三者行为分化，指向不同的收敛机制**：

| 指标 | ep10→70 趋势 | ep60→70 | 判读 |
|------|:---:|:---:|------|
| **PSNR** | 18.10 → 19.65（+1.55） | **-0.07** | 已在 ep60 达峰，ep70 进入平台/轻微过拟合 |
| **SSIM** | 0.702 → **0.740**（+0.038） | +0.0012 | **单调上升，ep70 仍是最优** |
| **LPIPS** | 0.337 → **0.320**（-0.017） | -0.0017 | **单调下降，ep70 仍是最优** |

**核心发现**：
1. **ep60 是 PSNR 峰值（19.716），ep70 是感知峰值（SSIM/LPIPS 最优）**——两者错位
2. ep50→60 的 +1.26dB 跃升纯粹由 lr 降档（4e-4 → 1e-4）触发：小 lr 下模型从"泛化探索"转入"细节精修"
3. ep60→70 的 PSNR -0.07 与 SSIM/LPIPS 继续改善并存 = **感知-保真度权衡点漂移**：模型在牺牲微小像素精度换取结构/纹理质量

## 二、注意力机制是否有效？

### 2.1 正面证据：正交约束确实解耦了三路特征

```
L_ortho 轨迹: ep1 = 2.96  →  ep70 = 0.0031   (降至 1/950)
```

三路特征 `F_N / F_L / F_M` 的归一化互相关从 0.99 降至接近 0，**证明特征空间解耦成功**。这是 TCA-RWKV 结构化查询设计的直接成果。

### 2.2 负面证据：解耦 ≠ 有效利用

| 对比 | 参数 | val PSNR | 结论 |
|------|:---:|:---:|------|
| TBC1B（单 TCA，0.89M）| 0.89M | 19.99@40 | 基线 |
| **Foxtrot（3×TCA-RWKV + 三分支，2.57M）** | 2.57M | 19.72@60 | **-0.27dB** |

**参数增加 2.9 倍，性能反而更低 0.27dB**。这说明：
1. TCA-RWKV 的**三路 RWKV 注意力算力**（每路 4 方向双向扫描）没有转化为性能
2. 三分支结构引入的**额外容量**未被有效利用，反而增加了优化难度

### 2.3 注意力有效性的深层诊断

**RWKV 注意力在本任务中的固有局限**：

```python
# tca_rwkv.py RWKVSpatialHead.forward
q_tokens = center_feat.flatten(2).transpose(1, 2)   # (B, N, C)
kv_tokens = context_feat.flatten(2)...              # 上下文是"降采样后的全局统计量"
# 关键: Q 来自中心帧, K/V 来自时序聚合上下文(非邻帧原始特征)
```

**问题**：RWKV 的 K/V 来自**聚合后**的时序上下文（mean/smooth/diff），而非**邻帧原始特征**。这意味着：
- RWKV 的空间扫描是在"已经坍缩的上下文"上做的，不是在真正的多帧特征上
- 与 Vision-RWKV 原始设计（对单帧空间做长程建模）的语义不一致
- **真正的跨帧对齐被 Branch-M 的独立光流模块接管**，TCA 实际只是"上下文增强器"

**结论：注意力机制"部分有效"**
- ✅ 正交约束实现了三路解耦（数学上成立）
- ✅ 提供了多帧上下文融合（有功能性）
- ❌ 未实现真正的"跨帧注意力"（K/V 不是邻帧特征）
- ❌ 相对简单基线没有性能优势（参数效率低）

## 三、模型整体结构与损失设计是否合理？

### 3.1 结构合理性评估

#### ❌ 严重问题 1：SharedEncoder 输出严重浪费

```python
# tsdnet.py:143-150
F1, F2, F3 = self.encoder(x[:, t])
pyramid_list.append((F1, F2, F3))
F1_seq = stack(...)   # (B,T,32,H,W)    ← 计算了但完全未使用
F2_seq = stack(...)   # (B,T,64,H/2,W/2) ← 唯一使用的
F3_seq = stack(...)   # (B,T,128,H/4,W/4) ← 计算了但完全未使用
```

**证据**：`F1_seq` 和 `F3_seq` 在后文再无引用。Encoder 计算了 3 个尺度，**只用了 1 个**——约 60% 的编码器算力浪费。

#### ❌ 严重问题 2：全流程 H/2 处理，无 skip connection

```
Encoder(H/2) → TCA(H/2,128²) → 三分支(H/2) → PixelShuffle×2 → Fusion(H)
```

- 所有语义处理在 H/2（256² 输入 → 128² 处理）
- 唯一的全分辨率信息是 Fusion 的 `X_t` 残差（且 gamma 从 0 学起）
- **高分辨率细节完全依赖 PixelShuffle 的参数化外推**

#### ⚠ 问题 3：Branch-M 的光流分辨率不足

```python
# branch_m.py: _align_and_aggregate
# F2_seq 是 H/2 尺度 → 光流在 128×128 估计
flow = self.flow_estimator(center, neigh)   # (B, 2, H/2, W/2)
```

SDSD 的 ±1-4px 运动在 H/2 下变成 ±0.5-2px，**光流量化误差达 50%**。这直接解释了 pair45（运动场景）的 PSNR 落后。

#### ⚠ 问题 4：Branch-M 用低层特征做光流

光流估计输入是 `F2_seq`（encoder 中间层 64ch），但参考帧是 `F_M`（TCA 运动分量 128ch）：
```python
center = F_M                    # 128ch, TCA输出
neigh  = self.neigh_proj(F2_seq[:, t])  # 64ch→128ch, 编码器输出
```
**两个特征空间不一致**（一个是 TCA 解耦的运动分量，一个是原始编码器特征），光流估计的"参照系"混乱。

### 3.2 损失设计评估

```
L_total = L_final + 0.3·L_N + 0.3·L_L + 0.3·L_M + 0.01·L_ortho + 0(L_temp)
```

| 项 | 设计 | 评估 |
|-----|------|------|
| L_final | L1 + 0.3·SSIM | ✓ 合理，主监督 |
| L_N/L_L/L_M | 各分支对 GT 监督 | ⚠ **三分支都监督到同一 GT，与"分支处理不同退化"的物理设定矛盾**——实际上三分支都在学完整增强，强制共享目标导致参数冗余 |
| L_ortho | 0.01 权重 | ✓ 有效解耦（0.003 收敛） |
| L_temp | 0（未启用） | ❌ **视频时序一致性损失完全缺失** |

**核心损失设计问题**：三分支各自回归到同一 GT，客观上鼓励三分支学到**相似的功能**——这与"分支专职处理不同退化"的设计初衷冲突。正交约束只约束了特征空间，没有约束**功能分工**。

### 3.3 与历史最佳（TBC1B）的结构对比

| 维度 | TBC1B | Foxtrot | 判读 |
|------|:---:|:---:|------|
| 参数 | 0.89M | 2.57M | Foxtrot 3× |
| 时序对齐 | LocalWindowAlignment（概念模型验证有效）| Branch-M 光流 | TBC1B 更简有效 |
| 光照 | ISPN 单模块 | Branch-L Retinex | 相当 |
| 解耦 | 无显式约束 | 三分支 + ortho | Foxtrot 过度设计 |
| val PSNR | 19.99@40 | 19.72@60 | **TBC1B 胜** |

## 四、问题诊断与解决方案

### 4.1 问题清单（按严重度）

| # | 问题 | 影响 | 解决难度 |
|---|------|------|:---:|
| P1 | F1/F3 特征闲置 | 60% 编码器算力浪费 | 低 |
| P2 | 全流程 H/2，无高分辨率 skip | 细节恢复瓶颈，pair45 差 | 中 |
| P3 | 三分支同监督同一 GT | 功能冗余，参数效率低 | 中 |
| P4 | 时序一致性损失缺失 | 帧间闪烁未约束 | 低 |
| P5 | Branch-M 光流分辨率/参照系问题 | 运动场景 PSNR 落后 | 中 |
| P6 | resume 覆盖 best.pth | 丢失最优权重 | 已修复 |

### 4.2 解决方案设计

#### 方案 A（最小改动，针对性）：修复 P1 + P4 + P6

**A1. 启用 F1 skip connection**（P1 + P2）
```python
# 在 fusion.py 前加入高分辨率 skip
# Branch-N/M 输出 Y_N/Y_M (H) 与 F1 (H,32ch) 融合
f1_center = F1_seq[:, self.center_idx]        # (B, 32, H, W)
skip_feat = self.skip_proj(f1_center)          # (B, 3, H, W)
Y_N = Y_N + skip_feat_alpha * skip_feat        # 可学习 α, 零初始化
```
**收益**：恢复原分辨率细节，预期 pair45 +0.3-0.5dB
**改动**：约 15 行

**A2. 启用 F3 coarse context**（P1）
```python
# F3 (H/4, 128ch) 作为全局上下文注入 TCA
f3_ctx = F.adaptive_avg_pool2d(F3_seq.mean(1), 1)   # 全局描述子
# 注入 TCA 的三路查询
```
**收益**：利用深层语义，约 +0.1-0.2dB
**改动**：约 20 行

**A3. 加入时序一致性损失**（P4）
```python
# loss.py: 对连续帧的输出做时序平滑
# 用相邻帧的增强结果做一阶差分约束
L_temp = F.l1_loss(O_t_curr, warp(O_t_prev))  # 需要多帧输出
```
**收益**：抑制帧间闪烁，提升视频质量（PSNR 提升有限但感知明显）
**改动**：约 30 行 + 训练循环改造

#### 方案 B（中等改动）：修复 P2 + P5

**B1. Branch-M 光流提升到 H 分辨率**
```python
# branch_m.py: 光流估计后在 H 分辨率做 warp
flow_h2 = self.flow_estimator(center, neigh)     # H/2
flow_h  = F.interpolate(flow_h2, scale_factor=2) # H
neigh_up = F.interpolate(neigh, scale_factor=2)  # H
warped = self.deform_align(neigh_up, flow_h)     # H 域 warp
```
**收益**：运动细节对齐精度提升，pair45 预期 +0.5dB
**代价**：算力 +40%（H 域光流）

**B2. 统一 Branch-M 的特征空间**
```python
# 用 F_M_seq (TCA 输出的全时序运动分量) 而非 F2_seq
```
**问题**：当前 TCA 只输出中心帧的 F_M，需要改 TCA 输出全序列
**改动**：较大（TCA 接口重构）

#### 方案 C（大改）：重构三分支监督（P3）

**C1. 分支差异化监督**
```python
# 不给三分支同一个 GT，而是给差异化目标
L_N = recon(Y_N, GT_low_freq)      # 噪声分支只看低频
L_L = recon(Y_L, GT_illum)          # 光照分支看全局亮度
L_M = recon(Y_M, GT_structure)      # 运动分支看结构
```
**问题**：如何构造这些分目标？可以用频域分解（GT 的低频/高频）或引导滤波分解
**收益**：强制功能分工，可能大幅提升参数效率
**风险**：分目标设计不当会引入伪影

### 4.3 推荐执行顺序

```
第一步（必做，1天）：方案 A1 + A3 + 修复 P6
  → skip connection 恢复细节 + 时序一致损失
  → 预计 val +0.3dB, pair45 +0.5dB

第二步（视第一步结果，1天）：方案 B1
  → 高分辨率光流对齐
  → 预计 pair45 +0.5dB

第三步（探索性）：方案 C1
  → 分支差异化监督，需要设计分目标
  → 高风险高回报
```

## 五、问题 3 的专项回答

### （1）SharedEncoder 的输出特征被充分利用了吗？

**没有。三路输出只用了 1 路（F2）。**

| 输出 | 分辨率 | 通道 | 使用情况 |
|------|:---:|:---:|------|
| F1 | H × W（原分辨率）| 32 | ❌ **完全未使用**（仅被 stack 进 F1_seq 后丢弃）|
| F2 | H/2 × W/2 | 64 | ✅ TCA + Branch-M 使用 |
| F3 | H/4 × W/4 | 128 | ❌ **完全未使用**（仅被 stack 进 F3_seq 后丢弃）|

**证据**（`tsdnet.py:148-150` 构造，后文无引用）：
```python
F1_seq = torch.stack([p[0] for p in pyramid_list], dim=1)  # 此后未使用
F2_seq = torch.stack([p[1] for p in pyramid_list], dim=1)  # 唯一使用
F3_seq = torch.stack([p[2] for p in pyramid_list], dim=1)  # 此后未使用
```

**后果**：
- 编码器约 2/3 的算力（F1 全分辨率 NAFBlock + F3 深层 NAFBlock）被浪费
- **F1 是全分辨率特征**，本可作为 skip connection 提供细节锚点——这是当前架构最可惜的浪费
- F3 是深层语义特征，本可提供全局上下文

**为什么会出现这个问题**：设计文档（TSD-Foxtrot.md §3.1）明确要求"输出三层金字塔特征"，但 TSDNet 实现时只取了 F2 给 TCA，F1/F3 的接口预留了却未接线。

### （2）所有特征在 H/2 处理，是否会抹除结构细节、小范围运动信息？

**是的，这是当前架构的核心缺陷。**

**处理分辨率全景**：
```
输入 256×256
  ↓ SharedEncoder
F1: 256×256 (32ch)   ← 未使用
F2: 128×128 (64ch)   ← 唯一使用
F3: 64×64  (128ch)   ← 未使用
  ↓ TCA-RWKV（仅 F2）
F_N/F_L/F_M: 128×128 (128ch)
  ↓ 三分支（全在 128×128）
Y_N/Y_L/Y_M: 256×256（经 PixelShuffle 上采样）
  ↓ Fusion（256×256）
O_t: 256×256
```

**细节丢失的两种机制**：

1. **结构细节丢失**：
   - 256→128 的下采样使 1px 宽的边缘/纹理变成 0.5px，在 3×3 卷积中模糊
   - 三分支在 128×128 处理后，PixelShuffle 从特征"外推"到 256×256
   - **没有来自 F1（原始 256×256）的 skip connection 作为细节锚点**
   - Fusion 的 X_t 残差是唯一的高分辨率信息，但 `residual_gamma` 零初始化（`fusion.py:67`），训练初期几乎不贡献

2. **小范围运动丢失**：
   - SDSD 的典型运动是 ±1-4px（256 分辨率下）
   - 下采样到 H/2 后变成 ±0.5-2px
   - **Branch-M 的光流在 128×128 估计**，±0.5px 的位移处于量化误差量级
   - 光流场 `flow_estimator` 输出被归一化除以 W/2=64（`branch_m.py:92`），0.5px 位移对应 0.0078 的归一化值——**信噪比极低**

**这解释了 pair45 的表现**：pair45 是最难的运动场景（±4px），Foxtrot 的 PSNR 14.76 落后 TBC1B（15.69）0.93dB——TBC1B 的 LocalWindowAlignment 在 H/2 做 9×9 局部窗口对齐（能覆盖 ±4px），而 Foxtrot 的全局光流在低分辨率下估计不准。

**解决方案**（对应 4.2 的 A1/B1）：
1. **加 F1 skip connection**：在分支输出/fusion 层面注入原始分辨率特征
2. **光流提升到 H 分辨率**：warp 操作在原始分辨率进行
3. **多尺度光流**：coarse-to-fine（H/4 → H/2 → H），借鉴 STA-SUNet 的 PCD

## 六、结论

| 问题 | 结论 |
|------|------|
| **注意力机制是否有效** | **部分有效**：正交约束成功解耦三路特征（L_ortho 2.96→0.003），但 K/V 来自聚合上下文而非邻帧原始特征，未实现真正的跨帧注意力；参数效率低（2.9× 参数却 -0.27dB）|
| **整体结构是否合理** | **存在严重浪费**：F1/F3 特征闲置（60% 编码器算力）、全流程 H/2 无 skip、Branch-M 光流分辨率不足 |
| **损失设计是否合理** | **部分合理**：主监督+正交约束有效；但三分支同监督同一 GT 导致功能冗余，时序一致性损失完全缺失 |
| **三指标综合表现** | PSNR 在 ep60 达峰（19.72），SSIM/LPIPS 在 ep70 达峰（0.740/0.320），感知-保真存在权衡错位 |
| **当前最优权重** | ⚠ best.pth 被 bug 覆盖为 ep70（19.6452）；真正 PSNR 最优是 ep60（19.7155）|

## 七、分格/棋盘格伪影诊断（2026-09-16 补充）

### 7.1 现象

用户观察推理帧存在"棋盘分格"现象。用 Read 工具直接查看 `outputs/foxtrot_r1/pair45_vis_ep70.jpg`（4 帧 × 3 列对比图）确认：
- 中间列（模型输出）有**约 224px 间隔的大尺度方块边界**
- 块内亮度不连续，块间有可见的亮暗跳变
- 部分区域伴随重影/对齐错误

### 7.2 根因 — 两个独立来源

**来源 A（主因）：`tiled_forward` 均匀平均导致缝线伪影**

```python
# utils/inference.py (修复前)
output[:, :, top:top+tile, left:left+tile] += tile_pred
weight[:, :, top:top+tile, left:left+tile] += 1.0
...
output = output / weight.clamp_min(1.0)
```

数值分析（1920×1080，tile=256，overlap=32，stride=224）：
- 非重叠区：权重 = 1.0
- 重叠带（32px）：权重 = 2.0
- 直接 `sum/weight` → **重叠带被两倍稀释** → 每 224px 出现一条亮度接缝

45 个 tile（5×9）的接缝正好对应观察到的 224px 分格。

**来源 B（次因）：三分支 PixelShuffle 上采样**

```python
# models/foxtrot/branch_{n,l,m}.py
self.upsample = nn.Sequential(
    nn.Conv2d(channels, channels * 4, 1, bias=True),   # 1×1 无感受野
    nn.PixelShuffle(2),                                 # 4通道→2×2子像素
    LayerNorm2d(channels),
)
```
- 1×1 卷积无空间混合，各子像素位置只由单一通道决定
- 训练后子像素通道梯度不均 → **2px 周期棋盘格**
- 频域指纹：自相关第一峰 = 2px（实测所有分支输出均为 2px）

### 7.3 修复（Golf 版本）

| 来源 | 修复 | 位置 |
|------|------|------|
| A | `tiled_forward` 改用 raised-cosine 窗口加权混合 | `utils/inference.py` |
| B | `PixelShuffle` → `UpsampleBlock` (resize-conv) | `models/golf/upsample.py` |

**修复 A 的关键细节**：窗口下限设 0.1（不是 0），避免图像边界单 tile 覆盖时权重归零产生黑边。边界处 `0.1*pred/0.1 == pred` 保持精确。

**修复 B 的原理**（Odena et al. 2016）：双线性插值是低通，不在 Nyquist 频率产生能量尖峰；后接 3×3 卷积提供可学习增强但保持空间连续性。

### 7.4 关键认识

1. **这不是训练问题** — 来源 A 在推理时即可复现，与权重无关；来源 B 是结构缺陷，再训练无法消除
2. **两个来源叠加** — 大尺度分格（224px，来源A）套小尺度棋盘（2px，来源B），视觉上呈现复杂的网格纹理
3. **验证方法** — 视觉（Read 图像）+ 数值（自相关第一峰、FFT Nyquist 频段能量）
