## 2. 单变量边界

四个 Core 配置除 `output_dir` 与 `model.q_mixer` 外完全相同，继续使用 legacy SGRFv9、
同一数据、损失、seed 和训练超参数。

SGRF-S0/S1 除 `output_dir` 与 `model.sgrf_v10_gate` 外完全相同：

- S0：`fixed`，三个阶段固定 \(G=1\)，融合模块无可训练参数；
- S1：`shared`，N/L/M 共用一个 449 参数的单通道 Gate；
- 两组都使用 Core-current、固定 N→L→M、最终 L1+0.1 MS-SSIM；
- 分支监督、频带目标、正交损失、Gate 正则和中间 clamp 全部关闭。

因此 S0→S1 的差值可以直接归因于共享 Gate。S0 相对旧模型则是“新分支残差接口 + 新状态
起点 + 新最终损失口径”的整体结构验证，不能拆解为某一个微小部件的独立收益。

## 3. 启动顺序

当前 Core-current 结束并完成结果核对前，不启动其他组。之后先确保同一代码提交已同步，再按
研究优先级逐组运行。SGRF-S0 必须先于 SGRF-S1；S1 不得读取或续训 S0 checkpoint，二者均
从相同随机种子独立训练。

SGRF 两组可直接执行：

```bash
python train_golf_v7r_v3.py --config configs/v9/v9_sgrfv10_s0_fixed_30ep.yaml
python train_golf_v7r_v3.py --config configs/v9/v9_sgrfv10_s1_shared_30ep.yaml
```

第二条命令只能在 S0 完整结束后启动。其余 Core 对照使用各自行对应的配置文件，不能把正在
训练的 Core-current 输出目录作为 `resume`。

## 4. 结果记录

六组统一记录 ep5/10/15/20/25/30 的 PSNR、SSIM、LPIPS，以及干净、加噪
\(\sigma=0.02/0.05\)、模糊 9px 和 N/L/M 置零结果。SGRF-S0/S1 另记录每阶段：

- `gate_N/L/M`：接纳均值（S0 恒为 1）；
- `delta_N/L/M`：分支提出的平均绝对修正量；
- `inc_N/L/M`：实际写入量 \(|G\odot\Delta|\)。

这些量只用于解释训练结果，不进入损失，也不据此临时修改本轮配置。

## 5. 初步有效性判定

- Core-current 首先与 CoReg 比较干净指标和 \(\sigma=0.05\) 鲁棒性；只有完成该主对照，
  span/wt/omni 的结果才用于讨论 Q-mixer。
- SGRF-S0 首先判断统一残差状态链能否稳定训练，以及三路是否产生非零写入。
- SGRF-S1 只与 S0 比较；只有 S1 在主指标、鲁棒性或明确的空间选择上带来稳定收益，才认为
  共享 Gate 有初步价值。
- 单次 30 epoch 只能证明初步有效性，不能写成统计显著或最终结论。
