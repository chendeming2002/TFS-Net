## 三、R5 设计回顾与失败分析

### R5 三项核心设计

#### 1️⃣ **动态时序门控 (temporal_gate)**
**设计意图**: 根据运动强度 `|Y_M - X_t|` 动态调整时序 vs 中心帧权重，在静态区域信任时序，在动态/瓦片边界回退中心帧。

**实际表现**:
```python
# Epoch 1 初期: tgate=0.731 (sigmoid(1.0) 初始值)
# Epoch 50:     tgate=0.740 (几乎无变化)
# lo(<0.3) = 0%, hi(>0.7) = 100%  # 从未激活中心帧回退
```

**失败原因**:
- **门控网络未学会区分静态/动态区域** — 100% 保持高信任时序
- **可能的问题**:
  1. 运动残差 `|Y_M - X_t|` 信号太弱（已经过 warp 对齐）
  2. Loss 未直接监督 gate 行为
  3. 静态场景占主导，网络学会"忽略"门控

#### 2️⃣ **Pair45 双指标早停 (best_pair45.pth)**
**设计意图**: 分别保存 val 最优和 pair45 最优检查点，防止 val 过拟合。

**实际表现**:
- `best_pair45.pth` (ep10): 15.78 dB
- `best.pth` (ep50): 14.78 dB
- **双指标策略有效** — ep10 确实是 pair45 最优点

**但核心问题**:
- **Ep10 的 15.78 dB 仍比 R2 差 1.44 dB** — 说明架构设计本身有缺陷，而非早停时机问题

#### 3️⃣ **选择性 R4 回退**
- **回退项**:
  - proj_out 零初始化 (R2)
  - 删除 FiLM
  - KV 聚合统计 (不 concat)
  - L_temp 空间 HF 上限 (R3)
  - prior_loss 权重 0.01→0.005

**失败原因**:
- **回退不彻底** — temporal_gate 引入新参数（4 个），打破了 R2 的隐式正则化
- **R2 的"双零死锁"可能确实是有益的正则** — R4/R5 删除后泛化能力崩溃

## 四、关键失败假设

### ❌ 假设1: "R2 的双零死锁是 bug"
**现实**: 可能是隐式正则化，限制了模型在单一场景过拟合的能力。R4/R5 解除限制后，模型快速过拟合验证集。

### ❌ 假设2: "动态门控能解决瓦片边界伪影"
**现实**: 门控网络未学会激活，100% 保持高时序权重。可能需要：
- 显式的瓦片边界位置编码
- 专门的边界伪影 loss
- 更强的运动信号（光流？）

### ❌ 假设3: "R4 性能差是 FiLM/KV-concat 引起的"
**现实**: R5 回退后 pair45 依然差。真正问题可能是：
- R2→R4 引入的**结构化先验正则 (prior_loss)** 改变了优化轨迹
- TCA 自身的表达能力限制（单头 RWKV，可能需要多头？）

## 七、失败根因总结

### 核心问题: **R2 的隐式正则被破坏，新机制未生效**

1. **R2 的"双零死锁"可能是特征** — 限制了过拟合，R4/R5 删除后模型快速在 val 上过拟合
2. **Temporal_gate 失效** — 设计合理但未学会激活，可能需要：
   - 显式监督信号（边界 mask loss）
   - 更强的运动特征（光流）
   - 门控网络容量不足（2层 Conv 可能太弱）
3. **Pair45 泛化问题根源未解决** — R2/R4/R5 都存在 val-pair45 分裂，说明：
   - 训练集与 pair45 场景差异大（可能是运动模式、噪声分布）
   - 需要 pair45 场景的数据增强或专门训练
4. **验证集评估不可靠** — 训练日志 pair45=11.30 vs 推理实测 14.78，差值 3.48 dB

## 八、经验教训

### ✅ 有效的设计
1. **Pair45 双指标早停** — 确实捕捉到了 ep10 最优点
2. **R5 config/train 脚本基础设施** — resume_from/strict=False 正确实现

### ❌ 失败的设计
1. **动态门控 temporal_gate** — 理论合理但实践失效，可能需要更强监督
2. **选择性 R4 回退** — 未能恢复 R2 性能，说明问题不在 FiLM/KV
3. **"修复=改进"假设** — R2 的"bug"可能是正则化特征

### 🔑 关键洞察
- **"Defect fixes ≠ performance improvement" (R4 教训) 在 R5 再次验证**
- **保守修改策略失败** — R5 试图最小化改动，但未找到问题根因
- **需要根本性架构创新** — R2→R4→R5 的渐进式改进已到瓶颈，pair45 泛化需要新范式

## 九、下一步建议

### 🚫 不建议继续 Golf 系列
- R2/R4/R5 均无法解决 pair45 泛化问题
- TCA-RWKV 单头架构可能有表达能力限制

### ✅ 建议新方向: **Flight11**

- **多尺度时序建模** — 金字塔结构，不同层级捕捉不同运动尺度
