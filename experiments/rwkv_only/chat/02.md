## 🔍 先诊断：概念模型是否"删减太多"？

看当前结构：
```
Encoder(3-stage) → [l1_center, TCA(l2), l3_center] → concat(192) → 3×conv → RGB
```

**这个结构本质上是 U-Net 的编码半支 + 单点时序融合 + 极浅解码头**。它缺失的是：

1. **没有解码上采样路径**：l3 (H/4) 直接 bilinear 上采样到 H，跳过了 stage 间的 refinement
2. **没有跨尺度信息流**：l3 的粗尺度信息无法与 l2 的中尺度对齐信息交互
3. **TCA 只在 H/2 单尺度做时序聚合**：H 和 H/4 都没做时序融合
4. **融合头只有 3 层 conv**：无法在运动区域全局判断信任 l1 还是 tca

但**是否"删减太多"要看目标**：
- 如果只是验证 TCA 可行性 → 结构合理
- 如果要解决运动模糊 → **确实删减过度**，缺失关键组件

## 🎯 运动模糊的根本原因（重新分析）

MOTION_BLUR_ANALYSIS 归因于 "C_omega 软对齐 + 低分辨率"，但这只说对了一半。**真正的原因链**：

```
低分辨率 C_omega (32×32)  ── 精确对应丢失
        │
        ▼
softmax 在多候选间发散 ── 加权平均模糊
        │
        ▼
Warp 后 f_omega 模糊  ── 但至此还只是 1/3 的 concat 输入
        │
        ▼ ★ 关键点
融合头 3×conv 学到什么？
  L1 loss 惩罚亮度差异 > 惩罚清晰度
  ⟹ 融合头学到用 tca_up 补亮度（因为多帧平均信噪比高）
  ⟹ 用 l1_feat 补高频（但 l1_feat 只有 64ch, tca_up 也是 64ch，权重相等）
  ⟹ **在运动区域，tca_up 的模糊被"平权"注入输出**
```

**问题不仅在 TCA，还在融合头的架构无法建立"运动检测→分支路由"能力**。

---

## 🔴 概念模型缺失的三个关键结构

### 缺失 1：多尺度时序融合

当前只在 H/2 做 TCA。但：
- **H 尺度**：小位移（1-3 像素）精确对齐，保留细节
- **H/2 尺度**：中位移（4-10 像素）结构对齐
- **H/4 尺度**：大位移（>10 像素）粗对齐，语义级

单尺度 TCA 意味着**大位移无法对齐**（因为 32×32 C_omega 每个格子对应 8×8 原始像素，位移 >4 像素就找不到对应）。反过来说，中心帧和邻帧的**小位移错位在 H/2 尺度被平均化**。

### 缺失 2：解码器路径 (U-Net skip)

`l3_up = bilinear(l3, H)` 直接跳到全分辨率。这意味着 **l3 的语义信息无法通过学习到的上采样精细化**。RWKV-Only 的表现之所以停在 19.80，很可能是因为它**没有学习上采样能力**。

真正的 U-Net skip：
```
l3 → upconv → +l2 → upconv → +l1 → head → RGB
```
每次上采样都由学习的 conv 完成，且注入低层 skip 特征。

### 缺失 3：运动感知的融合门控

融合头 `concat → 3×conv` 是**位置无关的静态融合**。它无法根据"这个位置是否运动"来动态调整 tca_up vs l1_feat 的权重。

MOTION_BLUR_ANALYSIS 提出的**方案 A（center_gate）**必须集成——但更好的做法是**放到融合头**，因为那里能同时访问 sharp 通路（l1）和 aligned 通路（tca）。

## 🎯 建议的概念模型重构

我建议一个**"最小可行的完整架构"**，仍然只有 Encoder + TCA + Decoder，但结构要真正闭环：

### 结构

```
Input (B, 5, 3, H, W)
  │
  ▼ PyramidEncoder
l1 (B,5,64,H,W)   l2 (B,5,64,H/2,W/2)   l3 (B,5,64,H/4,W/4)
  │                    │                     │
  │                    ▼                     ▼
  │              TCA_l2 (H/2)          TCA_l3 (H/4, lite)
  │              ├─ C_omega_l2         └─ f_aligned_l3
  │              └─ f_aligned_l2
  │                    │                     │
  ▼                    ▼                     ▼
[MotionGate_l1]   [MotionGate_l2]     f_l3_out
  │                    │                     │
  │ 使用 C_omega_l2   │ center_gate         │
  │ (upsampled)      │                     │
  │ 检测运动区域      │                     │
  │                    │                     │
  ▼                    ▼                     ▼
f_l1_out          f_l2_out             f_l3_out
  │                    │                     │
  │                    │◀─── upsample ───────┤
  │                    │  (learnable conv)
  │                    ▼
  │              f_l2_merged
  │                    │
  │◀─── upsample ──────┤
  │  (learnable conv)
  ▼
f_l1_merged
  │
  ▼ Head (conv 64→32→3)
res_t
```

### 关键机制

**1. 多尺度 TCA（重点在 l3, l2 各一次）**

l3 尺度做粗对齐（大位移）：
```python
# TCA_l3 只需要 lite 版本，因为分辨率低，通道可以少
# 但 C_omega_l3 提供大位移的语义级对齐
f_aligned_l3, C_omega_l3 = self.tca_l3(l3)
```

l2 尺度做主对齐（现有 TCA）：
```python
f_aligned_l2, C_omega_l2 = self.tca_l2(l2)
```

l1 尺度**不做 TCA**（H 分辨率下 attention 显存爆炸），但要用 C_omega 的运动图来**门控 l1 的中心帧**——这是关键。

**2. 运动图从 C_omega 提取，反注入 l1**

```python
def motion_map_from_C_omega(C_omega_list, target_hw):
    """C_omega 对角线偏离度 → 运动强度图
    对角线占优 → 静止（值高） → 输出 0
    对角线扩散 → 运动 → 输出 1
    """
    motion_scores = []
    for C in C_omega_list:  # 每个邻帧一个
        # C: (B, N, N), N=ds²
        diag = C.diagonal(dim1=-2, dim2=-1)  # (B, N) 对角占优程度
        motion = 1.0 - diag  # 越小越静止
        motion_scores.append(motion)
    motion = torch.stack(motion_scores, dim=1).mean(dim=1)  # (B, N)
    ds = int(N**0.5)
    motion_2d = motion.reshape(B, 1, ds, ds)
    return F.interpolate(motion_2d, size=target_hw, mode='bilinear')

# 在 l1 层
motion_map = motion_map_from_C_omega([C_omega_l2, ...], (H, W))
# motion_map ≈ 1 的区域 → 强运动 → 完全信任 l1 中心帧
# motion_map ≈ 0 的区域 → 静止 → 允许 tca 融合
```

**3. 学习上采样的解码器（而非 bilinear）**

```python
class UpBlock(nn.Module):
    def __init__(self, in_ch, skip_ch, out_ch):
        super().__init__()
        self.up = nn.ConvTranspose2d(in_ch, out_ch, 4, 2, 1)
        self.fuse = nn.Sequential(
            nn.Conv2d(out_ch + skip_ch, out_ch, 3, 1, 1),
            nn.GELU(),
            nn.Conv2d(out_ch, out_ch, 3, 1, 1),
        )
    def forward(self, x, skip):
        x = self.up(x)
        return self.fuse(torch.cat([x, skip], dim=1))

# 解码器
f_l2_merged = self.up_l3_to_l2(f_l3_out, skip=f_l2_out)   # H/4 → H/2
f_l1_merged = self.up_l2_to_l1(f_l2_merged, skip=f_l1_out) # H/2 → H
```

**4. 运动感知的融合门控**

```python
# 在最终融合前
sharp_gate = torch.sigmoid(motion_map * gain)  # (B,1,H,W)
# 运动区域 → sharp_gate→1 → 用 l1 中心帧（sharp）
# 静止区域 → sharp_gate→0 → 用融合后的 f_l1_merged（多帧降噪）
l1_center_sharp = l1[:, T//2]  # 原始尖锐中心帧
f_final = sharp_gate * l1_center_sharp + (1 - sharp_gate) * f_l1_merged
res_t = self.head(f_final)
```

## 🔴 为什么这个改动能解决运动模糊

对比当前架构：

| 机制 | 当前 RWKV-Only | 改进版 |
|------|:--:|:--:|
| 时序融合尺度 | 仅 H/2 | H/2 + H/4 双尺度 |
| 大位移处理 | 无法对齐 → 模糊 | l3 尺度粗对齐 |
| 解码器 | bilinear (不可学习) | ConvTranspose + skip |
| 运动区域路由 | 无（静态 concat） | motion_map 门控直连 sharp l1 |
| l1 中心帧信息 | 只在 concat 中占 1/3 | 运动区域直接主导输出 |

**决定性差异**：改进版能够 **在运动区域完全绕开 TCA 输出**，直接用原始 l1 中心帧。当前模型即使 TCA 输出模糊，融合头也无法学到"运动时忽略 tca"的能力，因为它只有 3 层局部感受野的 conv。

## 🎯 更激进的选择：完全不用 attention 对齐

如果实验证实"attention warping 在低分辨率下天然模糊"是不可解决的问题，还可以考虑：

**只做时序聚合，不做空间 warp**：
```python
# 抛弃 C_omega 空间 warp，只做帧级加权融合
# 让 conv 自己去学空间对齐
frame_weights = self.frame_gate(l2)  # (B, T, 1, H/2, W/2)
l2_agg = (l2 * frame_weights.softmax(dim=1)).sum(dim=1)
```

这相当于 3D convolution 的一个特例。它**放弃了显式对齐能力**，但避免了软对齐引入的模糊。运动区域的处理完全由后续 conv 学习。

对于**小位移场景**（SDSD-indoor 主要是小运动），这种简化可能反而更好——因为 attention warping 引入的成本大于收益。

**建议做个 ablation**：把当前 TCA 的 `TemporalAggregation` 部分换成简单的 3D conv 或帧级 attention（不做空间 warp），看 PSNR 是升是降。这个实验成本很低，但能明确 attention warping 的实际价值。

---

## 📋 推荐的实验顺序

| 顺序 | 改动 | 目的 | 预期 |
|:--:|------|------|:--:|
| 1 | 加**运动图门控 + l1 中心帧直连** | 最小改动测试运动模糊修复 | 运动区域清晰 |
| 2 | 加**学习上采样解码器** | 替换 bilinear | 整体细节提升 |
| 3 | 加 **l3 尺度 TCA lite** | 大位移对齐 | 复杂运动改善 |
| 4 | Ablation：移除 attention warp，改帧级加权 | 验证 warp 的实际价值 | 判断路线 |

**第 1 步是关键**：它成本最低（约 5K 参数），但直接针对报告的"运动模糊"现象。如果加了 motion_map + sharp bypass 后运动模糊消失，说明当前架构骨架是对的，只是缺少 sharp 通路；如果仍然模糊，说明 TCA 本身有更深的问题。

## 💡 元层面的反思

你之前问"是不是删减太多"——**是的，但不是删减 NDPN/MCPN 那些三分支**。

**真正被删掉的关键组件是：**
1. **解码器**（U-Net 的上采样半支）
2. **运动感知路由机制**（从时序对应中提取运动图，反向指导融合）
3. **多尺度时序融合**（不同尺度处理不同位移量级）

这三者是**任何视频恢复模型的基础组件**，与三分支的物理先验无关。当前概念模型把它们全部替换成 bilinear + concat + 3×conv，等于"用 MLP 头做 U-Net 任务"——能到 19.80 dB 已经是 TCA 主干能力的证明，但天花板就在那里。

**加回这三个基础组件**（预计参数量从 0.78M 升到 1.0-1.2M），才是概念模型该有的完整形态。之后再考虑是否需要三分支。
